## 二、28P01 / P1000 根因分析

### 2.1 直接原因
PostgreSQL 认证失败（28P01）和 Prisma 连接失败（P1000）

### 2.2 根本原因
1. **`.env.production` 中的 `DATABASE_URL` 包含 `?schema=public` 参数**
   - Prisma adapter-pg 不支持此参数
   - 导致连接字符串解析失败
   - PostgreSQL 日志显示：`password authentication failed for user "bxb_user"`

2. **PM2 启动脚本权限不足**
   - 错误：`spawn /home/deploy/xixiong-saas/scripts/pm2-start.sh EACCES`
   - 修复：`chmod +x scripts/pm2-start.sh`

3. **旧的 next-server 进程残留**
   - PID 2145740 使用旧环境变量
   - 导致端口 3000 被占用
   - 修复：`kill -9 2145740`

### 2.3 修复步骤
1. 修复 PM2 启动脚本权限
2. 移除 `.env.production` 中的 `?schema=public` 参数
3. 杀死旧的 next-server 进程
4. 完全重启 PM2（pm2 kill && pm2 start）
