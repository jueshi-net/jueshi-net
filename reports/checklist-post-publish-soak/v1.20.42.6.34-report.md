## 2. RelatedChecklistSection 硬编码根因

**问题：** address-formatter 和 shipping-calculator 的 `RelatedChecklistSection` 组件使用硬编码的 checklist 列表：

```tsx
// 修复前（硬编码）
<RelatedChecklistSection
  checklists={[
    { slug: "student-first-abroad-packing-checklist", ... }
  ]}
/>
```

**根因：** 这两个页面是 `'use client'` 组件，无法直接查询 Prisma 数据库。之前采用硬编码作为临时方案，但导致新发布的 checklist 不会自动出现在相关推荐中。

---

## 3. 动态推荐实现说明

### 实现方案

1. **新增 API 端点：** `GET /api/checklists`
   - 返回所有 `pageType="checklist"` 且 `status="published"` 的 checklist
   - 支持 `?slugs=...` 参数过滤指定 checklist
   - 返回格式：`{ data: [{ slug, title, summary, icon }] }`
   - draft/hidden checklist 不会出现在结果中

2. **组件升级：** `RelatedChecklistSection`
   - 新增 `toolSlug` 和 `showAll` props
   - 当提供 `toolSlug` 或 `showAll` 时，自动从 `/api/checklists` 获取数据
   - 保留向后兼容：如果提供 `checklists` props，优先使用静态数据
   - 加载状态显示「加载中...」
   - 请求失败静默处理，不影响主流程

3. **工具页更新：**
   - address-formatter: `toolSlug="address-formatter"`
   - shipping-calculator: `toolSlug="shipping-calculator"`

### 优势

- 新发布 checklist 自动出现在所有工具页的相关推荐中
- 无需修改工具页代码
- draft/hidden checklist 不会泄露到推荐列表
- 客户端加载，不影响 SSR 性能
