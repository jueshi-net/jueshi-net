### 3. 数据模型

**EventLog 模型**:
```prisma
model EventLog {
  id        String   @id @default(cuid())
  eventType String   @default("")
  toolName  String?
  action    String?
  path      String?
  sessionId String?
  createdAt DateTime @default(now())

  @@index([eventType])
  @@index([toolName])
  @@index([createdAt])
  @@index([sessionId])
  @@map("event_logs")
}
```

**ToolMetricDaily 模型**（已存在，用于工具指标日统计）

**Session 模型**（NextAuth 认证 session，非 analytics session）

## 五、是否需要 Migration

**需要**。原因：
1. 现有 `EventLog` 模型缺少关键字段（referrer, utm, device, browser, os, country, ipHash, durationMs, metadata）
2. 需要新增 `AnalyticsSession` 模型（可选）
3. 需要新增 `AnalyticsDailyRollup` 模型（可选）
4. 需要添加索引优化查询性能

**Migration 策略**:
- 方案 A：扩展现有 `EventLog` 模型（推荐，减少迁移风险）
- 方案 B：新增 `AnalyticsEvent` 模型（更清晰，但需要数据迁移）

**建议**: 采用方案 A，扩展现有 `EventLog` 模型，添加可选字段。

## 六、风险点

### 1. 性能风险
- ⚠️ 事件写入量大，需要合理索引
- ⚠️ 聚合查询可能慢，需要考虑日聚合
- ⚠️ 前端事件发送不能阻塞页面

### 2. 隐私风险
- ⚠️ 不能存储明文 IP
- ⚠️ 不能存储敏感输入（地址、电话、单号等）
- ⚠️ 需要更新隐私政策

### 3. 数据质量风险
- ⚠️ Bot / crawler 污染
- ⚠️ 重复事件
- ⚠️ 丢失事件（sendBeacon 失败）

### 4. 兼容性风险
- ⚠️ 旧浏览器不支持 sendBeacon
- ⚠️ 禁用 JavaScript 的用户无法统计
- ⚠️ Do Not Track 策略
