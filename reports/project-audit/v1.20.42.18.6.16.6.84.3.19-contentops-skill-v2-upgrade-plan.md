## 执行摘要

当前 ContentOps Bot 生成的内容质量简陋，主要原因是：
1. 缺乏内容质量门槛检查
2. 不支持长文本/文件/竞品资料输入
3. 缺乏 SEO/GEO 增强规则
4. 缺乏"洗稿/改写"安全规则
5. Telegram 交互过于简单

v2 升级方案将解决这些问题，实现高质量内容生成。

---

## 当前生成简陋的原因

### 1. 缺乏内容质量门槛

**现状**: Bot 生成内容后直接创建 draft，不检查质量。

**问题**:
- Checklist 可能只有 2-3 个 group，10 个 item
- Guide 可能只有 500 字，3 个 section
- Topic 可能只有 100 字 intro，2 个子主题
- FAQ 可能只有 2-3 个
- 缺乏 pitfalls、internalLinks、related tools

### 2. 不支持长文本/文件输入

**现状**: Bot 只支持简单文本输入，无法处理：
- 用户粘贴的长文章
- 用户上传的 PDF/Word 文件
- 竞品页面内容
- 参考资料

**问题**: Bot 只能基于简单提示生成内容，缺乏深度。

### 3. 缺乏 SEO/GEO 增强规则

**现状**: SEO/GEO 字段可选，不强制。

**问题**:
- metaTitle/metaDescription 可能缺失
- keywords 可能不完整
- structuredData 可能缺失
- FAQ schema 可能缺失

### 4. 缺乏"洗稿/改写"安全规则

**现状**: Bot 可能直接复制竞品内容。

**问题**:
- 版权风险
- 内容同质化
- 缺乏独特价值

### 5. Telegram 交互过于简单

**现状**: 用户只能发送简单文本，Bot 直接生成。

**问题**:
- 无法预览大纲
- 无法调整质量
- 无法指定目标用户
- 无法指定国家/地区

## 长文本/文件/竞品资料处理流程

### 流程 1: 长文本处理

```
1. 用户粘贴长文本 (500-5000 字)
2. Bot 识别内容类型 (checklist/guide/topic)
3. Bot 提取关键信息：
   - 标题
   - 目标用户
   - 国家/地区
   - 搜索意图
   - 关键步骤/要点
   - FAQ
   - 注意事项
4. Bot 生成大纲
5. 用户确认大纲
6. Bot 基于大纲生成完整内容
7. Bot 检查质量门槛
8. 用户确认创建 draft
```

### 流程 2: 文件处理

```
1. 用户上传文件 (PDF/Word/TXT)
2. Bot 解析文件内容
3. Bot 提取关键信息 (同流程 1)
4. Bot 生成大纲
5. 用户确认大纲
6. Bot 基于大纲生成完整内容
7. Bot 检查质量门槛
8. 用户确认创建 draft
```

### 流程 3: 竞品 URL 处理

```
1. 用户发送竞品 URL
2. Bot 抓取页面内容
3. Bot 提取关键信息 (同流程 1)
4. Bot 应用"洗稿/改写"安全规则
5. Bot 生成大纲
6. 用户确认大纲
7. Bot 基于大纲生成完整内容
8. Bot 检查质量门槛
9. 用户确认创建 draft
```

## 内容质量门槛

### Checklist 最低要求

| 字段 | 最低要求 | 检查规则 |
|------|---------|---------|
| title | 明确、具体 | 不得为空，不得过于宽泛 |
| intro | >= 150 中文字 | 字符计数 |
| groups | >= 4 | 数组长度 |
| items | >= 12 | 所有 group 的 items 总数 |
| item.description | 每个 item 必须有 | 不得为空 |
| FAQ | >= 5 | 数组长度 |
| pitfalls | >= 5 | 数组长度 |
| internalLinks | >= 5 | 数组长度 |
| relatedTools | >= 3 | 数组长度 |
| SEO/GEO | 完整 | metaTitle, metaDescription, keywords 必填 |
| structuredData | 完整 | FAQ schema, Checklist schema 必填 |

**如果达不到门槛**:
- 不创建 draft
- 返回"内容质量不足，需要补充资料或允许扩写"
- 列出缺失项

### Guide 最低要求

| 字段 | 最低要求 | 检查规则 |
|------|---------|---------|
| body | >= 1500 中文字 | 字符计数 |
| sections | >= 6 | 数组长度 |
| section.content | 每节有实用内容 | 不得只有标题 |
| FAQ | >= 5 | 数组长度 |
| pitfalls | >= 5 | 数组长度 |
| internalLinks | >= 5 | 数组长度 |
| relatedTools | >= 3 | 数组长度 |
| quickAnswer/summary | 必须有 | 不得为空 |
| SEO/GEO | 完整 | metaTitle, metaDescription, keywords 必填 |
| structuredData | 完整 | FAQ schema, Article schema 必填 |

**如果达不到门槛**:
- 不创建 draft
- 返回"内容质量不足，需要补充资料或允许扩写"
- 列出缺失项

### Topic 最低要求

| 字段 | 最低要求 | 检查规则 |

| recommendedTools | >= 8 | 数组长度 |

| internalLinks | >= 5 | 数组长度 |
| relatedGuides/Checklists/Tools | 必须有 | 不得为空 |
| SEO/GEO | 完整 | metaTitle, metaDescription, keywords 必填 |
| structuredData | 完整 | Topic schema 必填 |

**如果达不到门槛**:
- 不创建 draft
- 返回"内容质量不足，需要补充资料或允许扩写"
- 列出缺失项

## SEO/GEO 增强规则

### 强制字段

| 字段 | 类型 | 说明 |
|------|------|------|
| metaTitle | string | 60 字符以内，包含核心关键词 |
| metaDescription | string | 155 字符以内，包含 CTA |
| keywords | string[] | 5-10 个关键词 |
| searchIntent | string | informational/transactional/navigational |
| targetAudience | string | 目标用户描述 |
| country | string | 目标国家/地区 |

### 结构化数据

| 类型 | Schema | 说明 |
|------|--------|------|
| Checklist | ChecklistSchema | 包含 steps, items |
| Guide | ArticleSchema | 包含 sections, author, datePublished |
| Topic | TopicSchema | 包含 subtopics, relatedContent |
| FAQ | FAQSchema | 所有类型的 FAQ 统一使用 |

### 生成规则

1. **metaTitle**: 必须包含核心关键词，60 字符以内
2. **metaDescription**: 必须包含 CTA (Call to Action)，155 字符以内
3. **keywords**: 必须包含 5-10 个相关关键词
4. **searchIntent**: 必须明确指定
5. **targetAudience**: 必须明确指定
6. **country**: 必须明确指定

## 洗稿/改写安全规则

### 核心原则

1. **不逐句照搬**: 不得复制原文句子结构
2. **不复刻原文结构**: 必须重新组织内容结构
3. **不保留竞品独特表达**: 必须用自己的语言表达
4. **只提炼事实、流程、注意点**: 提取关键信息，不复制表达
5. **增加绝世百宝箱自己的结构**: 添加工具入口、FAQ、清单、风险提醒
6. **保留必要事实但重新组织语言**: 事实可以保留，表达必须原创
7. **如果来源明显受版权保护，不输出大段原文**: 避免版权风险
8. **如果用户上传文件，只基于资料做摘要、重构和原创表达**: 不复制文件内容
9. **生成报告中记录 sourceUsed=true，但不公开展示来源全文**: 内部记录，不公开
10. **如需要引用，使用短引用和来源说明**: 引用必须短小，必须注明来源

### 实施规则

#### 规则 1: 内容提取

```
输入: 竞品文章 / 用户资料
处理:
1. 提取关键事实 (数据、流程、步骤)
2. 提取关键注意点 (风险、注意事项)
3. 提取 FAQ (常见问题)
4. 忽略独特表达、修辞、故事
输出: 关键信息列表
```

#### 规则 2: 内容重组

```
输入: 关键信息列表
处理:
1. 重新组织结构 (不得与原文相同)
2. 添加绝世百宝箱工具入口
3. 添加 FAQ
4. 添加 pitfalls
5. 添加 internalLinks
6. 添加 relatedTools
输出: 新结构大纲
```

#### 规则 3: 内容生成

```
输入: 新结构大纲 + 关键信息
处理:
1. 用自己的语言重新表达
2. 添加实用建议
3. 添加工具推荐
4. 添加风险提醒
5. 检查质量门槛
输出: 原创内容
```

#### 规则 4: 版权检查

```
输入: 生成内容
处理:
1. 检查是否有大段相似内容
2. 检查是否有独特表达
3. 如有，重新表达
输出: 安全内容
```

## 后台 Draft 策略

### Draft 创建规则

1. **必须用户明确确认**: Bot 不得自动创建 draft，必须用户回复"确认生成草稿"
2. **必须通过质量门槛**: 内容必须满足最低要求
3. **必须包含完整 SEO/GEO**: metaTitle, metaDescription, keywords 必填
4. **必须包含 structuredData**: FAQ schema, type-specific schema 必填
5. **必须记录 sourceUsed**: 如果使用了参考资料，必须记录

### Draft 状态

- **status**: draft
- **publishedAt**: null
- **robots**: noindex,nofollow

### Draft 审核流程

1. 用户通过 Bot 创建 draft
2. Bot 返回 admin edit + admin preview 链接
3. 用户在后台审核内容
4. 用户修改内容 (如需要)
5. 用户手动发布 (需要 publication_allowed=true)

## 不自动发布策略

### 发布规则

1. **CONTENTOPS_PUBLICATION_ALLOWED=false**: 默认禁止发布
2. **必须用户明确确认**: 不得自动发布
3. **必须后台审核**: 必须在后台审核后才能发布
4. **必须检查质量**: 发布前必须再次检查质量

### 发布流程

1. 用户在后台审核 draft
2. 用户修改内容 (如需要)
3. 用户点击"发布"按钮
4. 系统检查质量门槛
5. 系统更新 status=published, publishedAt=now
6. 系统更新 robots=index,follow
7. 系统生成 sitemap

## 实施优先级

### Phase 1: 内容质量门槛 (P0 - 最高优先级)

**目标**: 确保生成的内容达到最低质量标准
