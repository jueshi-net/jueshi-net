### 历史 rsync 问题根因

v18.4.7.2/3 中 VPS 目录污染是因为 Hermes agent 手动执行 rsync 时使用了尾斜杠语法 `rsync ... prisma/ dest/`，导致 prisma 目录内容散落到 VPS 根目录。现有 `deploy-production.sh` 使用 `--exclude-from` + `./` 作为源，不会出现此问题。

## 2. 新增安全部署文件

### scripts/predeploy-check.sh
- 检查项目根目录 package.json/src/prisma/scripts 存在
- 检查无旧目录残留 (app/components/lib/hooks/migrations/schema.prisma)
- 检查 .env 不会被同步
- 检查 git status
- 运行本地 build (warning, VPS build 为准)
- 运行 unit tests (failure = abort)

### scripts/deploy-safe.sh
- 调用 predeploy-check.sh
- 调用 deploy-production.sh (rsync + VPS build + PM2 restart)
- 获取 VPS BUILD_ID
- 更新 deploy-version.json
- 验证 PM2 online
- 验证线上 deploy-version 一致
- 验证关键页面 200 + admin API 401
- 检查 PM2 error log
