## 根因分析

### 身份路由冲突

**问题：** Dev Bot（Hermes Gateway）和 ContentOps Bot 使用相同的 Telegram Bot Token，导致 409 Conflict

**证据：**
1. `.env.local` 中的 `CONTENTOPS_TELEGRAM_BOT_TOKEN` 前 8 位：`83098944`
2. `~/.hermes/.env` 中的 `TELEGRAM_BOT_TOKEN` 前 8 位：`83098944`
3. 两个 Token 完全相同
4. **Hermes Gateway 正在运行（PID 973）**，也在轮询同一个 Token
5. **ContentOps Bot 日志显示 409 Conflict 错误：**
   ```
   [polling_error] {"code":"ETELEGRAM","message":"ETELEGRAM: 409 Conflict: terminated by other getUpdates request; make sure that only one bot instance is running"}
   ```

**影响：**
- Hermes Gateway 和 ContentOps Bot 同时轮询同一个 Telegram Bot
- Telegram API 拒绝多个 getUpdates 请求
- ContentOps Bot 无法正常工作
- 用户消息只能被一个 Bot 接收，另一个会丢失

### PID 45311 分析

**进程命令：**
```
/Users/chq/.hermes/node/bin/node --require /Users/chq/.hermes/hermes-agent/node_modules/tsx/dist/preflight.cjs --import file:///Users/chq/.hermes/hermes-agent/node_modules/tsx/dist/loader.mjs scripts/contentops/contentops-telegram-bot.ts
```

**确认：** PID 45311 确实是 ContentOps Bot，运行 `scripts/contentops/contentops-telegram-bot.ts`

## 结论

**当前状态：** `TELEGRAM_POLLER_CONFLICT`

**原因：**
1. ✅ Hermes Gateway（PID 973）正在轮询 Telegram Bot Token
2. ✅ ContentOps Bot（PID 45311）也在轮询同一个 Token
3. ✅ 两个进程使用相同的 Token（前 8 位：83098944）
4. ✅ Telegram API 返回 409 Conflict 错误
5. ✅ ContentOps Bot 无法正常工作
6. ✅ 服务器 Bot 未运行
7. ❌ 轮询冲突导致 ContentOps Bot 被终止

**下一步：** 用户需要为 ContentOps Bot 创建独立的 Telegram Bot Token，避免与 Hermes Gateway 冲突。
