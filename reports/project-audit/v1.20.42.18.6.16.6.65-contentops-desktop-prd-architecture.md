## PHASE 1 — 产品定位

**文档路径:** `docs/contentops-desktop-prd.md`

### 核心要点

**产品名称:**
- 中文：绝世内容发布台
- 英文：Jueshi ContentOps Studio
- 代号：ContentOps Desktop

**产品定位:**
- 面向内容运营团队的桌面端内容生产管理工具
- 统一管理多平台内容创作、SEO/GEO 优化、审核排期和发布分发

**目标用户:**
- 内容运营（选题规划、内容创作、排期管理）
- SEO 专员（关键词研究、SEO 优化、排名监控）
- 内容编辑（内容审核、质量把控、发布确认）
- 站长/管理员（平台账号管理、权限配置、数据分析）

**桌面端 vs Web 后台职责边界:**

| 职责 | 桌面端 | 服务器端 |
|------|--------|---------|
| 内容编辑 | ✅ | ❌ |
| 审核预览 | ✅ | ❌ |
| 排期管理 | ✅ | ❌ |
| 本地缓存 | ✅ | ❌ |
| 密钥存储 | ❌ | ✅ |
| 定时任务 | ❌ | ✅ |
| 实际发布 | ❌ | ✅ |
| 数据库访问 | ❌ | ✅ |

**为什么密钥必须放服务器:**
1. 桌面端可被反编译，密钥泄露风险高
2. 服务器端可使用专业密钥管理服务（AWS KMS、HashiCorp Vault）
3. 平台要求密钥存储在安全环境
4. 法律合规要求（GDPR、数据安全法）

**MVP 范围 (V1):**
- Web 后台内容发布引擎
- jueshi.net 专题/指南/清单草稿
- SEO/GEO 评分
- 人工审核
- 定时发布
- 视频脚本包
- 平台发布包导出

**不做范围:**
- ❌ 违规模拟登录
- ❌ 全自动批量发布
- ❌ 密钥本地存储
- ❌ 垃圾内容生成
- ❌ 黑帽 SEO

## PHASE 4 — 内容流转状态机

### 12 个状态

```
idea → outline → draft → seo_checked → geo_checked
  → human_review → approved → scheduled → published_to_site
  → distributed_to_platforms → monitored → refresh_needed
```

### 状态转换规则

**每个状态定义:**
- 下一个允许状态
- 允许操作的角色
- 是否自动转换
- 自动转换条件
- 失败处理

**关键转换:**
- `draft → seo_checked`: 自动（SEO 评分 ≥ 60）
- `seo_checked → geo_checked`: 自动（GEO 评分 ≥ 60）
- `human_review → approved/draft`: 人工审核
- `scheduled → published_to_site`: 自动（到达发布时间）
- `monitored → refresh_needed`: 自动（流量下降 30% 或排名下降 5 位）

## PHASE 6 — 统一 Adapter 接口

### 接口定义

```typescript
interface PlatformAdapter {
  platform: string;
  capabilities: PlatformCapabilities;
  
  validate(content: ContentDraft): Promise<ValidationResult>;
  transform(content: ContentDraft): Promise<PlatformDraft>;
  createDraft(content: PlatformDraft): Promise<CreateDraftResult>;
  schedule(content: PlatformDraft, time: Date): Promise<ScheduleResult>;
  publish(content: PlatformDraft): Promise<PublishResult>;
  syncStatus(id: string): Promise<StatusResult>;
}

interface PlatformCapabilities {
  supportsDraft: boolean;
  supportsSchedule: boolean;
  supportsDirectPublish: boolean;
  supportsMediaUpload: boolean;
  supportsAnalytics: boolean;
  requiresManualReview: boolean;
  apiAvailable: boolean;
  riskLevel: 'low' | 'medium' | 'high';
}
```

### 实现示例

**jueshi.net Adapter:**
```typescript
class JueshiNetAdapter implements PlatformAdapter {
  platform = 'jueshi.net';
  capabilities = {
    supportsDraft: true,
    supportsSchedule: true,
    supportsDirectPublish: true,
    supportsMediaUpload: true,
    supportsAnalytics: true,
    requiresManualReview: false,
    apiAvailable: true,
    riskLevel: 'low',
  };
  
  async publish(content: PlatformDraft): Promise<PublishResult> {
    // 调用 jueshi.net API 发布
    const response = await fetch('https://jueshi.net/api/content/publish', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${await getApiKey()}` },
      body: JSON.stringify(content),
    });
    return { success: response.ok, ... };
  }
}
```

**微信公众号 Adapter:**
```typescript
class WeChatMPAdapter implements PlatformAdapter {
  platform = 'wechat-mp';
  capabilities = {
    supportsDraft: true,
    supportsSchedule: false,
    supportsDirectPublish: false,
    supportsMediaUpload: true,
    supportsAnalytics: true,
    requiresManualReview: true,
    apiAvailable: true,
    riskLevel: 'medium',
  };
  
  async publish(content: PlatformDraft): Promise<PublishResult> {
    // 只能创建草稿，需要手动发布
    const draftResult = await this.createDraft(content);
    return {
      success: draftResult.success,
      message: 'Draft created. Please publish manually.',
    };
  }
}
```

- PlatformAccount.refreshToken（Refresh Token）

**加密方案:**
```typescript
// AES-256-GCM 加密
function encrypt(text: string): string {
  const iv = randomBytes(16);
  const cipher = createCipheriv('aes-256-gcm', ENCRYPTION_KEY, iv);
  let encrypted = cipher.update(text, 'utf8', 'hex');
  encrypted += cipher.final('hex');
  const authTag = cipher.getAuthTag().toString('hex');
  return `${iv.toString('hex')}:${authTag}:${encrypted}`;
}
```

## PHASE 8 — 安全与合规

### 安全措施

**1. 密钥安全:**
- 平台密钥服务器端保存
- 桌面端只拿短期 session（24 小时过期）
- 使用 AWS KMS 加密存储

**2. 发布前人工审核:**
- 所有发布必须经过人工审核
- 质量评分 < 80 不允许提交审核
- 审核通过后才能发布

**3. 操作日志:**
- 记录所有创建/编辑/发布操作
- 日志保留 1 年
- 支持审计查询

**4. 回滚/下架记录:**
- 支持下架已发布内容
- 记录下架原因
- 从各平台同步下架

**5. 敏感词检查:**
- 内置敏感词库
- 发布前自动检查
- 发现敏感词阻止发布

**6. 平台规则检查:**
- 验证标题长度、内容长度
- 检查图片数量、外链
- 不符合规则阻止发布

**7. AI 内容质量检查:**
- 检查 AI 套话
- 检查重复内容
- 检查内容长度

**8. 禁止违规模拟登录:**
- ❌ 不使用 Selenium/Puppeteer
- ❌ 不使用 Cookie 注入
- ✅ 只使用官方 API

**9. 发布频率控制:**
- 微信公众号：1 篇/天，1 篇/小时
- YouTube：10 篇/天，5 篇/小时
- 知乎：5 篇/天，2 篇/小时
- 超限自动排队等待

### 是否建议做电脑版

**✅ 是，建议做电脑版**

**理由:**
1. **编辑体验** — 桌面端提供更流畅的富文本编辑体验
2. **离线能力** — 断网时可继续编辑，本地缓存草稿
3. **性能** — 本地渲染，响应更快，大文件处理不卡顿
4. **系统集成** — 可以调用本地应用，文件系统访问更方便
5. **多平台管理** — 统一管理多个平台的内容发布

**但是:**
- 密钥必须放服务器端（安全考虑）
- 定时任务必须放服务器端（7x24 运行）
- 实际发布操作必须放服务器端（平台回调）
