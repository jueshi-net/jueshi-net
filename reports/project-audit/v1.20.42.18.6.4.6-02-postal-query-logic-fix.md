# v1.20.42.18.6.4.6 — Postal Query Logic Fix

**Date:** 2026-06-22

## Root Cause

`looksLikePostalCode()` used regex `/^[A-Z0-9]{2,10}$/` which matched pure-alpha strings:
- "TORONTO" → true (7 chars, all letters) → treated as postal code
- "TOKYO" → true → treated as postal code
- "CALGARY" → true → treated as postal code

This caused city names to be routed to postal code region search:
- "Toronto" → searched for postal codes starting with "TOR" in Canada
- Canadian postal codes starting with "T" are in Alberta → returned Calgary/Edmonton

## Fix

### Client (postal-code-client.tsx)
```js
// Before:
return /^[A-Z0-9]{2,10}$/.test(normalized);
// After:
return /^[A-Z0-9]{2,10}$/.test(normalized) && /\d/.test(normalized);
```

### API (postal-codes/route.ts)
Same fix applied. Also fixed city search to use full query instead of 3-char prefix:
```js
// Before: const cityPrefix = query.trim().slice(0, 3);
// After: const cityQuery = query.trim();
```
