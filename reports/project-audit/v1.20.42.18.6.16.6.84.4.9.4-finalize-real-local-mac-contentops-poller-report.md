## 解决方案

### 方案 1: 修改 Bot 通过 HTTP API 创建 draft（推荐）

**步骤**:
1. 修改 Bot 代码，使用 fetch() 调用 /api/admin/topics
2. 配置 API 认证（admin session 或 API key）
3. 测试 API 调用
4. 在本地 Mac 启动 Bot

**优点**:
- 符合 singlePollerLocation=local_mac 要求
- 不需要数据库连接
- 架构清晰

**缺点**:
- 需要修改 Bot 代码
- 需要处理 API 认证
- 需要额外的开发和测试时间

**预计工作量**: 2-3 小时

### 方案 2: 使用 SSH 隧道连接生产数据库

**步骤**:
1. 配置 SSH 隧道: `ssh -L 5432:127.0.0.1:5432 jueshi-new`
2. 修改本地 DATABASE_URL 指向隧道
3. 在本地 Mac 启动 Bot

**优点**:
- 不需要修改 Bot 代码
- 可以直接使用 Prisma

**缺点**:
- SSH 隧道需要保持运行
- 网络延迟影响性能
- 安全风险（数据库暴露在本地）

**预计工作量**: 30 分钟

### 方案 3: 在服务器上启用 Hermes Agent（回退方案）

**步骤**:
1. 在服务器上配置 LOCAL_HERMES_ENABLED=true
2. 重启服务器上的 Bot
3. 让服务器上的 Bot 调用服务器上的 Hermes Agent

**优点**:
- 不需要修改 Bot 代码
- 不需要改变 Telegram polling 位置
- 生产环境更稳定

**缺点**:
- 违反 singlePollerLocation=local_mac 要求
- 需要在服务器上安装 Hermes Agent

**预计工作量**: 30 分钟

### 方案 4: 保持现状，接受 rule-based processing

**说明**:
- 服务器上的 Bot 使用 rule-based processing
- 不调用 Hermes Agent
- 不满足 singlePollerLocation=local_mac 要求
- 但可以正常工作

**优点**:
- 不需要任何改动
- 立即可用

**缺点**:
- 不调用 Hermes Agent
- 不满足架构要求

**预计工作量**: 0
