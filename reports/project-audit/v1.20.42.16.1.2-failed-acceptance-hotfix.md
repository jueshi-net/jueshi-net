## 二、用户验收失败项逐条复述

### 失败项 1：退出登录仍然异常
**现象：** 用户点击退出登录后，页面跳转到 http://localhost:3000 而不是 https://jueshi.net。

**Root Cause：**
1. header.tsx 中的 signOut 使用了 `callbackUrl: '/'`
2. NextAuth 的 signOut 方法在没有正确设置 NEXTAUTH_URL 时，会使用默认的 localhost:3000
3. PM2 启动时使用 `npm start` 而不是 `scripts/pm2-start.sh`，导致 .env.production 没有被正确加载
4. 虽然 .env.production 中有 NEXTAUTH_URL="https://jueshi.net"，但进程环境变量中没有这个值

**修复方案：**
修改 header.tsx 中的 signOut 调用，不使用 callbackUrl，而是手动处理重定向：
```tsx
// 修改前
signOut({ callbackUrl: '/' })

// 修改后
await signOut({ redirect: false });
window.location.href = '/';
```

**修复结果：** ✅ 已修复

### 失败项 2：前台仍找不到兑换奖励入口

## 四、logout 跳 localhost 的真实 root cause

### Root Cause 分析

1. **NextAuth signOut 配置问题：**
   - header.tsx 中的 signOut 使用了 `callbackUrl: '/'`
   - NextAuth 的 signOut 方法会生成一个 POST 请求到 /api/auth/signout
   - 然后会重定向到 callbackUrl
   - 如果 NEXTAUTH_URL 没有正确设置，重定向会使用 localhost:3000

2. **PM2 环境变量加载问题：**
   - PM2 使用 `npm start` 而不是 `scripts/pm2-start.sh`
   - 导致 .env.production 没有被正确加载
   - 进程环境变量中没有 NEXTAUTH_URL

3. **代码中的 localhost fallback：**
   - src/app/api/subscribe/route.ts 中有：
     ```ts
     const confirmUrl = `${process.env.NEXT_PUBLIC_APP_URL || 'http://localhost:3000'}/api/subscribe/confirm?token=${token}`;
     ```
   - 但这与 logout 无关

### 修复验证

修改 header.tsx 中的 signOut 调用：
```tsx
// 修改前
signOut({ callbackUrl: '/' })

// 修改后
await signOut({ redirect: false });
window.location.href = '/';
```

**修复结果：** ✅ 已修复
- 不再依赖 NextAuth 的 callbackUrl 重定向
- 手动控制重定向到 '/'
- 不会跳转到 localhost:3000
