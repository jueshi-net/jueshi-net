## 三、测试数据清理

### 3.1 测试任务链清理

**清理方式：**
```bash
# 清理测试用户的任务链
npx tsx -e "
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
async function main() {
  const testUsers = await prisma.user.findMany({
    where: { email: { startsWith: 'e2e-' } }
  });
  for (const user of testUsers) {
    await prisma.taskChain.deleteMany({ where: { userId: user.id } });
    console.log('Cleaned task chains for', user.email);
  }
}
main();
"
```

**清理频率：**
- ✅ 每次 E2E 测试后清理
- ✅ 每周清理一次测试数据
- ✅ Beta 测试结束后清理

---

### 3.2 测试奖励兑换清理

**清理方式：**
```bash
# 清理测试用户的奖励记录
npx tsx -e "
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
async function main() {
  const testUsers = await prisma.user.findMany({
    where: { email: { startsWith: 'e2e-' } }
  });
  for (const user of testUsers) {
    await prisma.userReward.deleteMany({ where: { userId: user.id } });
    // Reset user growth and points
    await prisma.user.update({
      where: { id: user.id },
      data: { growthValue: 0, points: 0, membershipTier: 'none', memberUntil: null }
    });
    console.log('Cleaned rewards for', user.email);
  }
}
main();
"
```

**清理频率：**
- ✅ 每次奖励测试后清理
- ✅ 每周清理一次测试数据

## 四、生产 E2E 规范

### 4.1 生产 E2E 运行频率

**必须遵守：**
- ✅ 生产 E2E 必须低频手动运行
- ❌ 不得在 CI 中自动运行
- ❌ 不得频繁运行（每天最多 1 次）

**原因：**
- 生产 E2E 会创建真实数据
- 频繁运行会污染生产数据库
- 可能影响真实用户体验

---

### 4.2 生产 E2E 失败处理

**必须遵守：**
- ✅ 生产 E2E 失败不得自动重试
- ✅ 失败后手动检查原因
- ✅ 清理失败测试创建的数据

**禁止：**
- ❌ 不得无限重试刷库
- ❌ 不得忽略失败
- ❌ 不得声称测试通过

---

### 4.3 生产 E2E 数据清理

**清理方式：**
- ✅ 测试后手动清理创建的数据
- ✅ 使用测试账号前缀 `e2e-`
- ✅ 清理任务链、奖励记录等

**禁止：**
- ❌ 不得留下测试数据
- ❌ 不得污染真实用户数据

---

## 五、测试数据隔离

### 5.1 测试用户不得变 admin

**必须遵守：**
- ✅ 测试用户必须是 `role=user`
- ❌ 测试用户不得是 `role=admin`
- ❌ 不得将测试用户提升为 admin

**原因：**
- Admin 权限过高，可能误操作
- 测试用户应该模拟真实用户

---

### 5.2 测试数据不得影响真实用户

**必须遵守：**
- ✅ 测试数据使用独立账号
- ✅ 测试数据使用独立任务链
- ✅ 测试数据使用独立奖励记录

**禁止：**
- ❌ 不得修改真实用户数据
- ❌ 不得删除真实用户数据
- ❌ 不得影响真实用户体验

---

## 六、Secret 管理

### 6.1 禁止输出的 Secret

**禁止输出：**
- ❌ DATABASE_URL（完整字符串）
- ❌ password hash
- ❌ cookie
- ❌ session
- ❌ token
- ❌ GitHub token
- ❌ SSH 私钥

---

### 6.2 Secret 存储

**必须遵守：**
- ✅ Secret 存储在 `.env.production`（VPS）
- ✅ Secret 存储在 `.env.local`（本地）
- ❌ 不得提交到 Git
- ❌ 不得在代码中硬编码

---

### 6.3 Secret 轮换

**建议：**
- 每 6 个月轮换一次 secret
- 轮换后更新所有环境
- 轮换后通知所有开发者

---

## 八、违规处理

### 8.1 违规行为

**违规行为：**
- 使用真实用户账号测试
- 输出 secret
- 污染生产数据
- 将测试用户提升为 admin

---

### 8.2 处理措施

**处理措施：**
- 立即停止测试
- 清理违规数据
- 通知所有开发者
- 记录违规原因
