## 一、执行摘要

### 1.1 任务目标

补充说明 9833416@qq.com 为什么会从 admin 变成 member，提供完整的根因分析。

### 1.2 核心发现

**根因已确认：** 会员兑换逻辑会覆盖 role 字段

- 当用户兑换 `member_trial` 类型的奖励时，代码会把 `role` 设置为 `"member"`
- 这会导致 admin 用户的 role 被覆盖为 "member"
- 这就是为什么 9833416@qq.com 的 role 从 admin 变成了 member

### 1.3 影响范围

**受影响账号：** 9833416@qq.com（唯一确认的 admin 用户）

**影响程度：**
- 无法访问后台管理页面（requireAdmin 检查失败）
- 无法使用 admin API 接口
- 无法执行管理员操作

**是否只有 9833416@qq.com 受影响：** 是（目前唯一确认的 admin 用户）

**是否有其他 admin 被降级：** 否（数据库中只有 9833416@qq.com 是 admin）

## 三、根因分析

### 3.1 问题代码位置

**文件：** `src/app/api/rewards/redeem/route.ts`

**问题代码：**
```typescript
// Auto-upgrade for member_trial: set role to member and update memberUntil
if (rewardItem.rewardType === "member_trial" && expiresAt) {
  const currentUser = await tx.user.findUnique({
    where: { id: userId },
    select: { memberUntil: true, role: true },
  });

  // Calculate new memberUntil: extend from current expiry or now
  const currentExpiry = currentUser?.memberUntil;
  const baseDate = (currentExpiry && currentExpiry > now) ? currentExpiry : now;
  const newMemberUntil = new Date(baseDate.getTime() + rewardItem.rewardValue * 24 * 60 * 60 * 1000);

  await tx.user.update({
    where: { id: userId },
    data: {
      role: "member",  // ← 问题：覆盖原有 role
      memberUntil: newMemberUntil,
    },
  });
}
```

### 3.2 问题流程

1. **用户兑换 member_trial 奖励**
   - 9833416@qq.com 兑换了 member_trial 类型的奖励
   - 兑换成功后，代码执行 `role: "member"`

2. **role 被覆盖**
   - 原本 role = "admin"
   - 被覆盖为 role = "member"

3. **后台权限检查失败**
   - `requireAdmin()` 检查 `role === "admin" || role === "管理员"`
   - 但 role 现在是 "member"
   - 权限检查失败，无法访问后台

### 3.3 时间线

```
2026-06-20 16:37:20.651  9833416@qq.com 兑换 member_trial 奖励
                          ↓
                          role 从 "admin" 变为 "member"
                          ↓
                          无法访问后台管理页面
```

## 四、代码审计

### 4.1 requireAdmin 权限检查

**文件：** `src/lib/auth/permissions.ts`

```typescript
export async function requireAdmin() {
  const res = await requireLogin();
  if ("error" in res) return res;

  if (!["admin", "管理员"].includes(res.role)) {
    return { error: new Response(JSON.stringify({ error: "Forbidden: Admin required" }), { status: 403 }) };
  }
  return { session: res.session, role: res.role };
}
```

**检查逻辑：**
- 检查 `role === "admin" || role === "管理员"`
- 如果 role 是 "member"，权限检查失败

### 4.2 会员检查逻辑

**文件：** `src/lib/membership.ts`

```typescript
export function isElevatedRole(role: string | undefined): boolean {
  return role === "admin" || role === "管理员";
}

export function isActiveMember(user: { role: string; memberUntil: Date | null } | null): boolean {
  if (!user) return false;
  
  // Admin/管理员 always has access
  if (user.role === "admin" || user.role === "管理员") return true;
  
  // Check if member has active membership
  if (user.role === "member") return true;
  
  return false;
}
```

**问题：**
- 会员检查使用 `role === "member"`
- 这会导致 admin 用户被误判为普通会员

### 4.3 前端显示逻辑

**文件：** `src/app/(workspace)/workspace/page.tsx`

```typescript
const memberLevel = user?.role === "管理员" ? "管理员" : user?.levelKey === "member" ? "会员" : "免费版用户";
```

**问题：**
- 前端使用 `role === "管理员"` 判断管理员
- 但数据库中 role 是 "admin"（小写）
- 这会导致显示错误

## 六、防复发方案

### 6.1 短期方案（推荐）

**方案 A：分离 role 和 membershipTier**

1. **新增 membershipTier 字段**
   ```prisma
   model User {
     role             String    @default("user")  // 仅用于权限：admin/user
     membershipTier   String    @default("free")  // 用于会员等级：free/member/premium
     memberUntil      DateTime? // 会员到期时间
   }
   ```

2. **修改会员兑换逻辑**
   ```typescript
   // 不再修改 role，只修改 membershipTier
   await tx.user.update({
     where: { id: userId },
     data: {
       membershipTier: "member",  // ← 不覆盖 role
       memberUntil: newMemberUntil,
     },
   });
   ```

3. **修改权限检查**
   ```typescript
   export async function requireAdmin() {
     const res = await requireLogin();
     if ("error" in res) return res;

     if (res.role !== "admin") {  // ← 只检查 role
       return { error: new Response(JSON.stringify({ error: "Forbidden: Admin required" }), { status: 403 }) };
     }
     return { session: res.session, role: res.role };
   }
   ```

**优点：**
- 清晰分离权限和会员等级
- 不会相互覆盖
- 易于理解和维护

**缺点：**
- 需要数据库 migration
- 需要修改多处代码

### 6.2 中期方案（备选）

**方案 B：使用 memberUntil 判断会员**

1. **不再修改 role**
   ```typescript
   // 只修改 memberUntil，不修改 role
   await tx.user.update({
     where: { id: userId },
     data: {
       memberUntil: newMemberUntil,  // ← 只修改到期时间
     },
   });
   ```

2. **使用 memberUntil 判断会员**
   ```typescript
   export function isActiveMember(user: { memberUntil: Date | null } | null): boolean {
     if (!user) return false;
     return user.memberUntil !== null && user.memberUntil > new Date();
   }
   ```

**优点：**
- 不需要新增字段
- 不需要修改 role 逻辑

**缺点：**
- 无法区分会员等级（member/premium）
- 需要修改多处代码

### 6.3 长期方案（不推荐）

**方案 C：保持现状，手动修复**

1. **手动恢复 9833416@qq.com 的 role**
   ```sql
   UPDATE users SET role = 'admin' WHERE email = '9833416@qq.com';
   ```

2. **不修改代码**
   - 保持现有逻辑
   - 每次兑换后手动恢复

**缺点：**
- 容易再次发生
- 需要人工干预
- 不可持续
