# v1.20.42.18.6.4.10-01 — Postal Query State Machine

## State Machine Definition

| State | Trigger | Display Text |
|-------|---------|-------------|
| `idle` | No query entered | 请输入城市、邮编或地址关键词开始查询 |
| `loading` | Query in progress | 正在查询当前国家数据库... |
| `country_no_database` | Country not in COUNTRIES_WITH_DB | 当前国家暂未接入可查询邮编数据库，请使用地址格式或官方入口确认 |
| `no_match` | Country has DB but 0 results | 未找到匹配结果，请检查邮编格式、城市英文名，或使用官方入口确认 |
| `exact_match` | Postal code exact match | [Results displayed] |
| `city_match` | City name matched | [Results displayed] |
| `region_match` | Province/state matched | [Results displayed] |
| `error` | Query failed | 查询失败，请稍后重试 |

## Implementation

### API (`/api/postal-codes/route.ts`)
- `COUNTRIES_WITH_DB = Set(['CA','US','GB','AU','NZ','JP','SG','MY'])`
- If country not in set → returns `status: 'country_no_database'`
- If postal code search → exact + prefix match on `normalizedPostalCode`
- If city search → city + areaName + province + adminName1 with alias mapping
- Returns `status` field in every response

### Advanced API (`/api/postal-codes/advanced/route.ts`)
- `noMatchForSelectedCountry` only `true` when country NOT in COUNTRIES_WITH_DB
- Previously was always `true` when results=0 — now correctly distinguishes

### Client (`postal-code-client.tsx`)
- `dbStatus` state: `'idle' | 'no_match' | 'country_no_database' | 'exact_match' | 'city_match' | 'region_match' | 'error'`
- State machine drives UI display
- `no_match` shows: "未找到匹配结果" + "当前国家已有邮编数据库，但输入的关键词未匹配到任何记录"
- `country_no_database` shows: "当前国家暂未接入可查询邮编数据库"
