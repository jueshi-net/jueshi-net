## 二、问题背景

用户实测发现 Telegram 告警存在以下问题：

1. **重复告警**：同一组故障状态未变化时，每 5 分钟重复发送相同内容
   - disk: 85% used
   - nginx_5xx: 27 errors

2. **消息格式问题**：Telegram 中换行显示为字面量 `\n`，可读性差

3. **nginx_5xx 检测逻辑问题**：使用静态 "last 1000 requests" 导致旧错误反复触发

4. **磁盘告警阈值策略缺失**：85% 持续刷屏，无静默周期

## 三、修复内容

### 3.1 告警去重逻辑

**实现方案**：

1. **状态哈希比对**
   - 每次检查后，将所有故障项的 `name:status:message` 排序后生成哈希
   - 与上次告警的哈希比对
   - 哈希相同 = 状态未变，哈希不同 = 状态变化

2. **静默周期（Reminder Cycle）**
   - 同一故障状态未变化时，首次告警后静默 60 分钟
   - 60 分钟后发送一次 reminder（提醒）
   - reminder 后继续静默 60 分钟

3. **状态变化立即告警**
   - 新增故障：立即告警
   - 故障升级（如 disk 85% → 90%）：立即告警
   - 故障降级（如 disk 90% → 85%）：立即告警
   - 故障恢复：发送恢复通知

4. **状态文件持久化**
   - 路径：`logs/health-check-state.json`
   - 记录内容：
     - 每个检查项的 status、message、time
     - `_alert_hash`: 上次告警的哈希
     - `_alert_time`: 上次告警时间（epoch）
     - `_reminder_time`: 上次 reminder 时间（epoch）
     - `_recovery_sent`: 已发送恢复通知的项目列表

**代码实现**：
```bash
# Build current alert signature (sorted list of "name:status:message")
ALERT_SIG=""
for name in "${ALERTS[@]}"; do
    ALERT_SIG+="${name}:${CHECK_STATUS[$name]}:${CHECK_MESSAGE[$name]}|"
done
ALERT_SIG=$(echo "$ALERT_SIG" | tr '|' '\n' | sort | tr '\n' '|' | head -c -1)
ALERT_HASH=$(echo -n "$ALERT_SIG" | md5sum | cut -d' ' -f1)

# Determine what to send
if [ "$ALERT_HASH" != "$PREV_ALERT_HASH" ]; then
    SHOULD_SEND_ALERT=true
    SEND_REASON="state_changed"
elif [ "$TIME_SINCE_LAST" -ge "$REMINDER_INTERVAL" ]; then
    SHOULD_SEND_ALERT=true
    SEND_REASON="reminder"
else
    echo "[dedup] Skipping alert: same state" >> "$LOG_FILE"
fi
```

### 3.2 Telegram 消息格式修复

**问题原因**：
- 旧脚本使用 `\n` 字面量字符串
- curl 未使用 `--data-urlencode`，导致换行符未正确编码

**修复方案**：
1. 使用 bash 的 `$'\n'` 语法生成真实换行
2. curl 使用 `--data-urlencode` 参数自动编码

**修复前**：
```bash
ALERT_TEXT="🚨 jueshi.net Health Check Alerts\\nHost: $HOSTNAME\\nTime: $TIMESTAMP"
curl -d "text=${ALERT_TEXT}" ...
```

**修复后**：
```bash
ALERT_MSG="🚨 jueshi.net Health Check Alerts"
ALERT_MSG+=$'\n'"Host: $HOSTNAME"
ALERT_MSG+=$'\n'"Time: $TIMESTAMP"
ALERT_MSG+=$'\n'
ALERT_MSG+=$'\n'"Failures:"
for detail in "${ALERT_DETAILS[@]}"; do
    ALERT_MSG+=$'\n'"  • $detail"
done

curl --data-urlencode "text=${ALERT_MSG}" ...
```

**消息格式示例**：
```
🚨 jueshi.net Health Check Alerts
Host: iZt4nhejwjiz3ng6n2dcaZ
Time: 2026-06-17 05:19:05

Failures:
  • disk: 85% used
  • nginx_5xx: 27 new 5xx errors since last check

Disk: 85%
PM2: online
```

### 3.3 nginx_5xx 检测逻辑修复

**问题原因**：
- 旧脚本使用 `tail -1000` 读取最后 1000 行日志
- 这是静态窗口，包含旧错误，导致反复触发告警
- PM2 停止测试产生的 502 错误会长期存在

**修复方案**：
1. **增量检测**：记录上次读取的日志偏移量
2. **只统计新增错误**：从上次偏移量开始读取，只统计新增的 5xx 错误
3. **日志轮转处理**：如果日志文件大小变小（轮转），重置偏移量

**实现代码**：
```bash
NGINX_LOG="/var/log/nginx/access.log"
NGINX_OFFSET_FILE="$LOG_DIR/nginx-offset.txt"

# Get last read offset
LAST_OFFSET=0
if [ -f "$NGINX_OFFSET_FILE" ]; then
    LAST_OFFSET=$(cat "$NGINX_OFFSET_FILE" 2>/dev/null || echo "0")
fi

# Get current file size
CURRENT_SIZE=$(stat -c%s "$NGINX_LOG" 2>/dev/null || echo "0")

# If file was rotated (current size < last offset), reset
if [ "$CURRENT_SIZE" -lt "$LAST_OFFSET" ] 2>/dev/null; then
    LAST_OFFSET=0
fi

# Count new 5xx errors since last offset
if [ "$CURRENT_SIZE" -gt "$LAST_OFFSET" ] 2>/dev/null; then
    ERROR_COUNT=$(sudo tail -c +$((LAST_OFFSET + 1)) "$NGINX_LOG" 2>/dev/null | \
        grep -cE ' HTTP/1\.[01]" 5[0-9]{2} ' 2>/dev/null || true)
else
    ERROR_COUNT=0
fi
ERROR_COUNT=$(echo "$ERROR_COUNT" | tr -d '[:space:]')

# Save current offset
echo "$CURRENT_SIZE" > "$NGINX_OFFSET_FILE"
```

**优势**：
- 只统计新增错误，不会重复告警
- 日志轮转后自动重置
- 测试期间产生的旧错误不会长期触发告警

### 3.4 磁盘告警阈值策略

**实现方案**：

| 阈值 | 级别 | 告警策略 |
|---|---|---|
| < 80% | ok | 不告警 |
| 80% - 89% | warning | 首次告警，静默 60 分钟 |
| 90% - 94% | critical | 首次告警，静默 60 分钟 |
| ≥ 95% | critical (EMERGENCY) | 立即告警，建议缩短 reminder 周期 |

**代码实现**：
```bash
DISK_USAGE=$(df / | tail -1 | awk '{print $5}' | sed 's/%//')
if [ "$DISK_USAGE" -lt 80 ] 2>/dev/null; then
    record_check "disk" "ok" "${DISK_USAGE}% used"
elif [ "$DISK_USAGE" -lt 90 ] 2>/dev/null; then
    record_check "disk" "warning" "${DISK_USAGE}% used"
elif [ "$DISK_USAGE" -lt 95 ] 2>/dev/null; then
    record_check "disk" "critical" "${DISK_USAGE}% used"
else
    record_check "disk" "critical" "${DISK_USAGE}% used (EMERGENCY)"
fi
```

**当前状态**：
- 磁盘使用率：85%
- 级别：warning
- 告警策略：首次告警后静默 60 分钟

## 六、Reminder 静默周期

**配置**：
```bash
REMINDER_INTERVAL=3600  # 60 分钟
```

**工作流程**：

1. **首次告警**（T=0）
   - 检测到故障
   - 发送告警
   - 记录 `_alert_time = T`, `_reminder_time = T`

2. **5 分钟后**（T=300s）
   - 检测到相同故障
   - 检查：`T - _alert_time = 300s < 3600s`
   - 检查：`T - _reminder_time = 300s < 3600s`
   - **不发送告警**，记录 `[dedup] Skipping alert`

3. **60 分钟后**（T=3600s）
   - 检测到相同故障
   - 检查：`T - _reminder_time = 3600s >= 3600s`
   - **发送 reminder**
   - 更新 `_reminder_time = T`

4. **65 分钟后**（T=3900s）
   - 检测到相同故障
   - 检查：`T - _reminder_time = 300s < 3600s`
   - **不发送告警**

5. **120 分钟后**（T=7200s）
   - 检测到相同故障
   - 检查：`T - _reminder_time = 3600s >= 3600s`
   - **发送 reminder**

**优势**：
- 避免刷屏（每 5 分钟重复）
- 保持可见性（每 60 分钟提醒）
- 状态变化立即告警
