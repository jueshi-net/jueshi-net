## 概述

实现了 LandingPage 的模块（block）显示/隐藏控制和排序功能的完整闭环，包括后台管理 UI、前台渲染逻辑、以及 Analytics 追踪。

---

## 实现内容

### 1. 数据模型 ✅

Prisma schema 中 `LandingPage` 模型已包含以下字段（此前已存在）：

```prisma
blockVisibility  Json?  @map("block_visibility")  // {hero: true, primaryTool: true, ...}
blockOrder       Json?  @map("block_order")       // ["hero", "primaryTool", ...]
```

- `blockVisibility`: JSON 对象，key 为模块名，value 为 boolean（`false` 表示隐藏，默认/缺失 = 可见）
- `blockOrder`: JSON 数组，定义模块渲染顺序

### 2. API 路由 ✅

**文件**: `src/app/api/admin/landing-pages/route.ts`  
**文件**: `src/app/api/admin/landing-pages/[id]/route.ts`

- GET: 新增 `blockVisibility` 和 `blockOrder` 到 select 字段
- POST: 新增 `blockVisibility` 和 `blockOrder` 到 create data
- PUT: 新增 `blockVisibility` 和 `blockOrder` 到 update data（条件更新）

### 3. 后台管理 UI ✅

**文件**: `src/app/(admin)/admin/landing-pages/landing-pages-client.tsx`

新增「📦 模块显示与排序」控制面板，功能包括：

- **10 个模块开关**：Hero 横幅、主工具卡片、热门城市、相关工具、相关专题、相关文章、相关清单、FAQ、官方链接、CTA
- **Checkbox 切换**：勾选/取消控制模块是否在前台显示
- **上下箭头排序**：调整模块在前台的渲染顺序
- **序号显示**：直观展示当前排序位置
- **视觉反馈**：隐藏的模块显示为删除线灰色文字
- **默认行为**：未配置时所有模块默认可见，使用默认顺序

### 4. 前台渲染 ✅

**文件**: `src/app/(public)/lp/[slug]/page.tsx`

- 从数据库读取 `blockVisibility` 和 `blockOrder`
- 计算有效渲染顺序（blockOrder 优先，缺失时使用默认顺序）
- 按可见性过滤模块（`blockVisibility[key] !== false` 才渲染）
- 每个渲染的 section 添加 `data-block` 属性供 Analytics 追踪
- 使用 switch/case 结构按 order 动态渲染各模块

### 5. Analytics 追踪 ✅

**文件**: `src/lib/analytics/index.ts`  
**文件**: `src/app/(public)/lp/[slug]/block-tracker.tsx`

新增事件类型：
- `landing_page_block_view`：模块进入视口时触发（IntersectionObserver）
- `landing_page_block_click`：模块内点击时触发

追踪实现：
- `BlockViewTracker` 客户端组件使用 IntersectionObserver 监听 `data-block` 元素
- 每个模块仅追踪一次（避免重复上报）
- 携带 `slug` 和 `blockName` 元数据

### 6. 测试验证 ✅

**文件**: `scripts/test-block-control.mjs`

20 个测试用例全部通过：
- 默认行为（null 值）→ 10 个模块全部可见
- 空对象 → 等同于默认
- 隐藏单个模块 → 正确过滤
- 隐藏多个模块 → 正确过滤
- 自定义排序 → 按指定顺序渲染
- 排序 + 可见性组合 → 正确交集
- 无效 key 过滤 → 安全忽略
- 显式 true → 等同于默认可见
