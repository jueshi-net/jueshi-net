# v1.20.42.18.6.4.7-02 邮编查询可信数据降级模式

## 根因分析

### Bug 1: API `country || 'US'` 默认值
- **位置**: `/api/postal-codes/route.ts` line 71
- **问题**: `params = [country || 'US', ...]` — 当 country 为空时默认搜索美国
- **影响**: 马来西亚邮编 50000（5位数字）→ 无国家参数时搜索 US → 返回美国结果
- **修复**: 移除 `|| 'US'` 默认值，改为显式分支：有国家→国家隔离查询，无国家→全库搜索

### Bug 2: `detectCountryFromPostal` 忽略用户选择的国家
- **位置**: `/api/postal-codes/advanced/route.ts` line 142-165
- **问题**: 当 CITY_MAPPINGS 无匹配时，调用 `detectCountryFromPostal(normalized)` 猜测国家
- **影响**: 用户选马来西亚 + 输入 50000 → detectCountryFromPostal 返回 'US'（5位数字→US）→ 返回美国结果
- **修复**: 当 `countryCode` 已提供时，跳过 `detectCountryFromPostal`；返回 `noMatchForSelectedCountry: true` + 官方入口

### Bug 3: 客户端 `handleMainSearch` 只查 region 不查 DB
- **位置**: `postal-code-client.tsx` line 705-718
- **问题**: 邮编查询只走 `searchAdvancedRegion`（静态城市映射+格式猜测），不走 `queryDb`（真实数据库）
- **影响**: 马来西亚 50000 有真实数据库记录，但因为走的是 region search 而非 DB search，所以查不到
- **修复**: 邮编查询同时触发 `queryDb`（真实DB）和 `searchAdvancedRegion`（格式信息）

## 修复后的查询优先级

1. **精确邮编匹配** — DB 查询 `normalizedPostalCode = query`
2. **城市精确匹配** — DB 查询 `city ILIKE 'Toronto%'`
3. **城市别名匹配** — DB 查询 `areaName ILIKE 'Toronto%'`
4. **无结果状态** — 显示"未找到精确结果" + 官方入口

## 国家隔离保证
- DB 查询: `WHERE "countryCode" = $1` — 严格限制在选定国家
- Region 查询: `if (countryCode && city.countryCode !== countryCode) continue;` — 跳过其他国家
- `detectCountryFromPostal`: 仅在 `!countryCode` 时调用
