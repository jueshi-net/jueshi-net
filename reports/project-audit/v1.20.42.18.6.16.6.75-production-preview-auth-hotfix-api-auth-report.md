## PHASE 8 — API E2E 认证问题排查

### 尝试 1：直接 API 调用

```bash
curl -s -X POST "https://jueshi.net/api/admin/checklists" \
  -H "Content-Type: application/json" \
  -d '{...}'
```

**结果：** `{"error":"Unauthorized"}`

### 尝试 2：获取 CSRF Token

```bash
curl -s "https://jueshi.net/api/auth/csrf"
```

**结果：** ✅ 成功获取 CSRF token

### 尝试 3：登录获取 Session

```bash
curl -s -X POST "https://jueshi.net/api/auth/callback/credentials" \
  -H "Content-Type: application/json" \
  -d '{"csrfToken":"...","email":"...","password":"..."}'
```

**结果：** ⚠️ 返回 302 redirect，但未获取 session cookie

### 认证阻塞原因

| 因素 | 状态 | 详情 |
|------|------|------|
| CSRF | ✅ 可获取 | Token 获取成功 |
| Credentials | ⚠️ 未验证 | 登录返回 302 但无 session |
| Callback URL | ✅ 正确 | `/api/auth/callback/credentials` |
| Cookie Domain | ⚠️ 未确认 | 可能受 secure cookie 影响 |
| Secure Cookie | ⚠️ 可能 | Production 可能要求 HTTPS + secure flag |
| Admin Role | ⚠️ 未验证 | 无法确认 session 中的 role |
| Route Middleware | ✅ 存在 | `/api/admin/*` 需要 admin session |

**结论：** curl API E2E 不适合当前 auth 体系，因为：
1. NextAuth session cookie 可能受 secure flag 保护
2. curl 无法处理复杂的 session 管理
3. 需要浏览器环境或专用 CLI 工具
