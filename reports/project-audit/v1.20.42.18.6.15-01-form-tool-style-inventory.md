## 2. 推荐归类

### 2.1 统一标准单据（Standard Document）— 走动态路由 `[type]/page.tsx`

**25 种**动态路由单据全部适合统一模板。它们共享：
- 统一表单字段（document-fields.ts 定义）
- 统一预览渲染
- 统一导出（PDF + Word）
- 统一公司资料选择器
- 统一商品选择器
- 统一草稿保存/恢复
- 统一单据链路
- 统一工具内容
- 统一 BBS 联动

### 2.2 个性化自定义表单（Custom Form）— 保留独立路由和 UI

| 工具 | 理由 |
|------|------|
| 供应链报价单 | 独立 UI 有多步骤表单、商品行内编辑、链路导航，不适合统一模板 |
| Debit Note | 借记通知格式特殊，有独立的金额计算逻辑 |
| 入库单 | 仓库场景，有货物行、签收区，UI 与标准单据差异大 |
| 交接单 | 货物交接场景，有交接方/接收方/签收，布局独特 |
| 标签打印 | 热敏纸打印，尺寸/分页/数量控制是核心，完全不同的渲染形态 |
| 拍单脚本 | AI 生成型工具，非表单，是脚本生成器 |
| 报关单生成器 | 使用 jsPDF 独立导出，表格结构特殊 |
| 收据/发票 | 简单表单，但格式独立 |

### 2.3 实用工具（Utility）— 完全独立

邮编查询、HS Code、汇率、计算器、二维码、地址格式化、ZIP、运费计算、敏感货查询、集装箱计算、备忘录 — 这些是查询/计算类工具，不是表单工具，不需要接入 Document Runtime。

### 3.2 核心问题

1. **能力重复实现**：公司资料、草稿、导出在 6+ 个独立工具中各自实现，维护成本高
2. **能力不一致**：Debit Note/入库单/交接单没有 Word 导出、没有商品资料、没有工具内容
3. **审计盲区**：独立工具审计覆盖不完整
4. **无法扩展**：新增个性化工具需要从零实现所有公共能力

## 4. 结论

### 应统一的（数据能力层）
- 公司资料选择/填充
- 草稿保存/恢复/历史
- PDF/Word 导出
- 会员门禁/权益检查
- 审计日志
- 商品资料选择/填充

### 应保留个性化的（视觉模板层）
- 供应链报价单的多步骤表单 UI
- 标签打印的热敏纸布局
- 入库单的货物行+签收区
- 交接单的交接方布局
- Debit Note 的金额计算 UI
- 拍单脚本的 AI 生成界面

### 架构方向
**统一底座 + 自由模板**：公共能力通过 Runtime Hooks 注入，视觉模板完全自由。个性化工具通过 `CustomFormShell` 选择性接入公共能力，不改变自身 UI。
