# v1.20.42.18.6.4.10-04 — Postal Task Chain 404 Fix

## Root Cause

The postal code client used `/auth/signin` as the login redirect URL. The application's login route is `/login`, not `/auth/signin`. This caused a 404 when unauthenticated users clicked "加入任务链".

## Files Fixed

1. `src/app/(public)/tools/postal-code/postal-code-client.tsx` — All `/auth/signin` → `/login`
2. `src/app/preferences/page.tsx` — `/auth/signin` → `/login`
3. `src/app/(public)/tools/container/page.tsx` — `/auth/signin` → `/login`
4. `src/app/(public)/tools/hs-code/page.tsx` — `/auth/signin` → `/login`
5. `src/app/notifications/page.tsx` — `/auth/signin` → `/login`

## Verification

- Browser check: `document.body.innerHTML.includes('/auth/signin')` → `false` ✅
- Task chain route `/workspace/task-chains/shipping/new` returns HTTP 200 ✅
- Unauthenticated flow: redirects to `/login?callbackUrl=...` (no 404) ✅
