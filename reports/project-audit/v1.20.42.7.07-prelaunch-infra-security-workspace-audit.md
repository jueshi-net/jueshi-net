  email     String
  token     String   @unique

### 推广系统方案

**方案 A: 简单推广链接（无奖励）**

**需要 Migration**: 否

**实现**:
1. User 模型已有 `referrer` 字段（Text 类型）
2. 注册时读取 URL 参数 `?ref=xxx`
3. 查找 `inviteCode.code === ref` 的邀请码
4. 将邀请码的 `createdBy` 写入新用户的 `referrer`
5. 用户端展示推广链接: `/register?ref={user.inviteCode}`

**缺点**:
- 需要为每个用户手动创建邀请码
- 无奖励机制

**方案 B: 自动推广链接 + 奖励（推荐）**

**需要 Migration**: 是

**新增字段/模型**:
```prisma
// User 模型新增
model User {
  inviteCode    String?  @unique // 用户唯一邀请码
  referredBy    String?  @map("referred_by") // 邀请人 User ID
  referralCount Int      @default(0) @map("referral_count") // 邀请人数
}

// 新增邀请奖励模型
model ReferralReward {
  id          String   @id @default(cuid())
  inviterId   String   @map("inviter_id")
  inviteeId   String   @map("invitee_id")
  rewardDays  Int      @map("reward_days")
  createdAt   DateTime @default(now())
  
  @@unique([inviterId, inviteeId])
  @@map("referral_rewards")
}
```

**实现**:
1. 用户注册时自动生成 `inviteCode` (8位随机字符串)
2. 注册时读取 `?ref=xxx`，查找对应用户
3. 绑定 `referredBy`
4. 邀请人 `referralCount++`
5. 创建 `ReferralReward` 记录
6. 邀请人 `memberUntil` 增加奖励天数
7. 用户端展示:
   - 我的推广链接
   - 复制链接按钮
   - 已邀请人数
   - 获得会员天数
8. 后台配置:
   - 是否启用邀请奖励
   - 每邀请1人奖励天数
   - 是否限制奖励次数

**风控**:
- 同 IP 检测（使用 `ipHash`）
- 自邀请防护（`inviterId !== inviteeId`）
- 管理员可撤销异常奖励

**预计工作量**: 2-3 天

**建议**: 先实施方案 A（快速上线），后续迭代实施方案 B
