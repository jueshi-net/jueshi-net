## 三、推荐位方案 A 实现说明

### 3.1 实现方式

**核心思路**: 复用 `sortOrder` 字段标识推荐位

**规则**:
- `sortOrder < 0`: 推荐位资源（数值越小优先级越高）
- `sortOrder = 0`: 普通资源（默认）
- `sortOrder > 0`: 降权资源

### 3.2 前台查询逻辑

**文件**: `src/app/(public)/resources/page.tsx`

```typescript
// 查询推荐位资源：sortOrder < 0，排除广告
let featuredResources = await prisma.resource.findMany({
  where: {
    isActive: true,
    isAd: false,
    sortOrder: { lt: 0 },
  },
  orderBy: [
    { sortOrder: "asc" }, // 更小的值（更负）排在前面
  ],
  take: 12, // 最多展示 12 个推荐位
});

// Fallback: 如果没有推荐位，使用高质量资源
if (featuredResources.length === 0) {
  featuredResources = await prisma.resource.findMany({
    where: {
      isActive: true,
      isAd: false,
      qualityScore: { gte: 70 },
    },
    orderBy: [
      { qualityScore: "desc" },
      { createdAt: "desc" },
    ],
    take: 6,
  });
}
```

### 3.3 前台渲染逻辑

**文件**: `src/app/(public)/resources/resource-directory-client.tsx`

- FeaturedTools 组件接收 `featuredResources` prop
- 渲染 DB 查询结果，而非静态配置
- 每个推荐位显示网站图标、名称、"外部网站"标识
- 所有链接添加 `rel="noopener noreferrer nofollow"`

### 3.4 后台管理

**文件**: `src/app/(admin)/admin/resources/page.tsx`

- 后台已有 `sortOrder` 编辑功能
- 管理员可设置 `sortOrder = -1, -2, -3` 等负值来标识推荐位
- 数值越小，推荐优先级越高

### 3.5 验收标准达成

- ✅ `/resources` Featured 区域数据来自 DB 查询
- ✅ 不再依赖硬编码静态列表
- ✅ `/admin/resources` 可通过 sortOrder 管理推荐排序
- ✅ 无 schema 变更
- ✅ 无 migration
- ✅ 无生产批量 update
- ✅ 物流资源不会在 Featured 中过度集中（取决于管理员设置）
