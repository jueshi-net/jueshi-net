## A. Discourse

### 技术栈
- 后端: Ruby on Rails
- 前端: Ember.js (SPA)
- 数据库: PostgreSQL
- 缓存: Redis
- 搜索: PostgreSQL Full-Text Search

### 核心功能
- **分类/标签**: Categories + Tags 双维度，支持子分类
- **信任等级**: Trust Level 0-4，自动晋升，高等级用户获得更多权限
- **审核机制**: 社区标记 + 自动标记 + 队列审核，新用户帖子需审批
- **通知机制**: 多渠道通知（回复、提及、关注、消息），可细粒度配置
- **搜索**: PostgreSQL 全文搜索，支持中文分词（需插件）
- **插件机制**: 官方插件 + 第三方插件，Ruby gem 形式
- **后台管理**: 完整 Admin Dashboard，站点设置、用户管理、审核队列
- **反垃圾**: Akismet 集成、rate limiting、新用户限制、链接限制

### License
- **GPL v2** — 传染性 copyleft 许可证
- **不可直接复制代码** 到非 GPL 项目
- 只能借鉴设计理念

### 对 jueshi.net 的价值
- ✅ 信任等级系统 → 借鉴为新用户发帖频率限制
- ✅ 审核队列 → 借鉴为 pending 状态 + admin 审核
- ✅ 置顶/锁定 → 已实现 (isPinned, isLocked)
- ✅ IP hash 反垃圾 → 已实现 (ipHash 字段)
- ❌ 不可复制代码（GPL v2）

### 不适合直接采用的原因
- Ruby on Rails 技术栈与 jueshi.net (Next.js) 不兼容
- GPL v2 license 限制
- 过重（需要独立 PostgreSQL + Redis 部署）
- 无法与现有 User/NextAuth 集成

## B. Flarum

### 技术栈
- 后端: PHP (Laravel 组件)
- 前端: Mithril.js (轻量 SPA)
- 数据库: MySQL/MariaDB
- 缓存: Redis (可选)

### 核心功能
- **轻量讨论流**: 无限滚动，快速加载，移动端优先
- **扩展机制**: 1200+ 扩展，Composer 包管理
- **移动端体验**: PWA 支持，移动端原生体验
- **标签/分类**: Tags 为主，Categories 为辅

### License
- **MIT** — 最宽松的许可证
- 理论上可复制代码，但 PHP 代码对 Next.js 项目无用

### 对 jueshi.net 的价值
- ✅ 移动端优先设计 → 借鉴为 mobile-first 社区页面
- ✅ 轻量讨论流 → 借鉴为无限滚动帖子列表
- ✅ 标签系统 → 当前只有 category，可增加 tags JSON 字段
- ✅ PWA 概念 → 后续考虑

### 不适合直接采用的原因
- PHP 技术栈不兼容
- 虽然是 MIT license，但代码无法直接用于 Next.js 项目
- 独立部署，无法与现有用户系统集成

## C. NodeBB

### 技术栈
- 后端: Node.js (Express)
- 前端: 自定义模板引擎 + 部分实时渲染
- 数据库: Redis / MongoDB / PostgreSQL
- 实时通信: Socket.IO (WebSocket)

### 核心功能
- **实时通知**: WebSocket 推送，即时通知
- **插件系统**: Node.js 包形式
- **REST API**: 完整的读写 API
- **移动端**: 响应式设计，PWA 支持

### License
- **GPL v3** — 传染性 copyleft，比 GPLv2 更严格
- **不可直接复制代码**

### 对 jueshi.net 的价值
- ✅ 技术栈最接近（Node.js 生态）→ API 设计可参考
- ✅ 实时通知概念 → 二期可用 Server-Sent Events 实现轻量实时通知
- ✅ REST API 设计 → 当前 API 路由设计已类似
- ✅ 插件/钩子系统 → 借鉴为事件驱动架构

### 不适合直接采用的原因
- GPL v3 license 限制
- 独立部署，需要 Redis/MongoDB
- 无法与 NextAuth + Prisma + PostgreSQL 直接集成

## D. Forem

### 技术栈
- 后端: Ruby on Rails
- 前端: React (Preact)
- 数据库: PostgreSQL
- 搜索: Elasticsearch
- 缓存: Redis

### 核心功能
- **文章 + 讨论 + 标签**: 长文 + 评论 + 标签的混合模式
- **用户主页**: 个人主页展示文章和互动
- **内容分发**: Feed 算法，个性化推荐
- **社区治理**: 行为准则、举报、版主体系

### License
- **AGPL v3** — 最严格的 copyleft
- 网络服务使用也必须开源
- **绝对不可复制任何代码**

### 对 jueshi.net 的价值
- ✅ 文章 + 讨论混合模式 → Guide/Topic + ForumPost 的组合
- ✅ 社区治理理念 → 版主体系、行为准则
- ✅ 标签内容分发 → 后续推荐流参考
- ✅ 用户主页 → 二期用户主页参考

### 不适合直接采用的原因
- AGPL v3 license 最严格，绝对不可用于商业项目
- Ruby on Rails 不兼容
- 需要 Elasticsearch（过重）
- 无法集成

## License 风险结论

| 项目 | License | 可否复制代码 | 可否借鉴设计 |
|------|---------|-------------|-------------|
| Discourse | GPL v2 | **否** | 是 |
| Flarum | MIT | 是（但 PHP 代码无用） | 是 |
| NodeBB | GPL v3 | **否** | 是 |
| Forem | AGPL v3 | **否** | 是 |

**结论:** 所有 4 个项目都只适合借鉴设计理念，不复制任何代码。jueshi.net 社区论坛应基于现有 Next.js + Prisma + PostgreSQL 技术栈自研。
