# v1.20.42.18.6.4.11-01 — Postal Match Semantics

## Match Type Definitions

| Status | Meaning | Display Label |
|--------|---------|---------------|
| `exact_postal_match` | Complete postal code exact match | 精确匹配 (green badge) |
| `prefix_range_match` | Only prefix matched, full code doesn't exist | 前缀范围参考 (amber badge + warning) |
| `city_match` | City name matched | 城市匹配 (blue badge) |
| `region_match` | Province/state matched | 地区匹配 (purple badge) |
| `no_match` | Country has DB but no results | 未找到匹配结果 |
| `country_no_database` | Country has no DB | 当前国家暂未接入可查询邮编数据库 |

## API Changes (`/api/postal-codes/route.ts`)

- `exact_match` → split into `exact_postal_match` and `prefix_range_match`
- Checks if ANY result has `normalizedPostalCode === normalized` (exact)
- If no exact match but prefix matches exist → `prefix_range_match`
- Returns `matchDetail` object with `hasExactMatch` and `isPrefixOnly` flags

## Client Changes

- `dbStatus` type updated to include new statuses
- Results header shows colored badge: 精确匹配 / 前缀范围参考 / 城市匹配 / 地区匹配
- `prefix_range_match` shows amber warning: "⚠️ 未找到该完整邮编的精确记录，以下结果基于邮编前缀匹配的区域参考。"
