## 九、失败根因

### 根本原因

v1.20.42.10.2 在修复数据库查询问题时：
1. 重置了 PostgreSQL 中 bxb_user 的密码
2. 更新了 .env.production
3. **但没有更新 .env.local**
4. **没有同步 PM2 环境变量**

导致：
- .env.local 中的 DATABASE_URL 指向错误的端口（5555）和旧密码
- Next.js 构建时优先使用 .env.local，导致构建失败
- PM2 应用使用旧的环境变量，导致数据库连接失败

### 教训

1. **环境配置一致性**：修改数据库密码时，必须同步更新所有环境配置文件（.env.production、.env.local、.env.development 等）
2. **PM2 环境变量**：修改环境变量后，必须使用 `pm2 delete` + `pm2 start` 完全重新加载，而不是简单的 `pm2 restart`
3. **备份脚本**：crontab 配置的任务必须有对应的脚本，否则任务会失败
4. **构建依赖**：Next.js 构建时需要访问数据库，必须确保数据库连接正常
