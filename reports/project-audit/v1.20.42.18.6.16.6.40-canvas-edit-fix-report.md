Previously, attempting to edit any saved canvas template resulted in "This page couldn't load" error. The root cause was a schema mismatch between stored templates and the canvas editor's expectations.

---

## Root Cause Analysis

### The Problem

When loading a saved template, the canvas editor executed:
```typescript
const loadedTemplate = data.data;
setCanvas(loadedTemplate);  // CRASH: loadedTemplate lacks required fields
```

### Schema Mismatch

**Stored Template (TemplateConfig):**
```json
{
  "id": "user-1782534104413",
  "name": "测试模板-审计161",
  "toolKey": "...",
  "origin": "user",
  "ownerId": "...",
  "fields": [...],
  "columns": [...],
  "contentBlocks": [...],
  "style": {...},
  "layout": {...},
  "bindings": {...},
  "createdAt": "...",
  "updatedAt": "..."
}
```

**Canvas Editor Expectations (CanvasTemplate):**
```typescript
{
  mode: "canvas",
  name: string,
  paper: CanvasPaperConfig,      // ❌ MISSING
  elements: CanvasElement[],     // ❌ MISSING
  grid: CanvasGridConfig,        // ❌ MISSING
  batch?: CanvasBatchConfig,     // ❌ MISSING
  createdAt: string,
  updatedAt: string
}
```

### Why This Happened

1. **Save Logic:** Canvas editor sends `config: canvas` (CanvasTemplate with `paper`, `elements`, etc.)
2. **POST Handler:** Treats it as `TemplateConfig`, spreads fields
3. **Storage:** Template is saved, but canvas-specific fields (`paper`, `elements`, `grid`, `batch`) are either:
   - Lost during validation/normalization
   - Overwritten by default TemplateConfig fields
   - Not properly persisted due to schema validation

4. **Load Logic:** Attempts to use the stored TemplateConfig as a CanvasTemplate → crashes when accessing undefined `paper`, `elements`, etc.

## The Fix

### Code Changes

**File:** `src/app/(public)/tools/template-studio/canvas-editor-full.tsx`

**Before:**
```typescript
useEffect(() => {
  if (templateId && !template) {
    fetch(`/api/template-studio/templates/${templateId}`)
      .then(res => res.json())
      .then(data => {
        if (data.success && data.data) {
          const loadedTemplate = data.data;
          setCanvas(loadedTemplate);  // ❌ Crashes if missing canvas fields
          setCurrentTemplateId(loadedTemplate.id);
          if (loadedTemplate.selectedCompanyId) {
            setSelectedCompanyId(loadedTemplate.selectedCompanyId);
          }
        }
      })
      .catch(err => console.error("Failed to load template:", err));
  }
}, [templateId, template]);
```

**After:**
```typescript
useEffect(() => {
  if (templateId && !template) {
    fetch(`/api/template-studio/templates/${templateId}`)
      .then(res => res.json())
      .then(data => {
        if (data.success && data.data) {
          const loadedTemplate = data.data;
          
          // Check if this is a canvas template (has paper/elements)
          // If not, it's a structured template or corrupted — use default canvas
          const hasCanvasData = loadedTemplate.paper && loadedTemplate.elements;
          
          if (hasCanvasData) {
            // Valid canvas template — load it
            setCanvas(loadedTemplate);
          } else {
            // Not a canvas template — start with default canvas
            // but preserve the name and ID
            const defaultCanvas = defaultCanvasTemplate();
            setCanvas({
              ...defaultCanvas,
              name: loadedTemplate.name || "未命名模板",
            });
            console.warn("Template is not a canvas template, starting with default canvas");
          }
          
          setCurrentTemplateId(loadedTemplate.id);
          if (loadedTemplate.selectedCompanyId) {
            setSelectedCompanyId(loadedTemplate.selectedCompanyId);
          }
        }
      })
      .catch(err => console.error("Failed to load template:", err));
  }
}, [templateId, template]);
```

### Key Improvements

1. **Graceful Fallback:** If template lacks canvas data, initialize with default canvas instead of crashing
2. **Preserve Metadata:** Template name and ID are preserved even when canvas data is missing
3. **Clear Warning:** Console warning helps developers identify non-canvas templates
4. **No Data Loss:** Existing templates remain accessible; users can re-edit and re-save
