## 九、迁移难度评估

### 迁移复杂度：中

**预计迁移步骤：** 15-20 步  
**预计停机时间：** 30-60 分钟（如果先预同步）  
**最大风险：**
1. PM2 日志清理后重新启动
2. 数据库恢复
3. .env 缺失
4. Nginx/SSL 配置
5. DNS 切换

### 推荐迁移策略

**阶段 1：准备（1-2 天）**
1. 清理 PM2 日志（释放 98.5G）
2. 删除 bxb_test_restore 数据库（释放 1.8G）
3. 清理重复备份（释放约 2G）
4. 提交所有未提交文件
5. 创建迁移文档（RESTORE.md, env-keys.md）
6. 降低 DNS TTL 到 300

**阶段 2：新服务器演练（1 天）**
1. 在新服务器安装依赖（Node.js, PostgreSQL, Nginx, PM2）
2. 克隆代码
3. 恢复数据库
4. 配置 .env.production
5. 配置 Nginx + SSL
6. 配置 PM2
7. 配置 Crontab
8. 运行 build 和 smoke test
9. **不改 DNS**

**阶段 3：最终迁移（停机 30-60 分钟）**
1. 停止旧服务器 PM2
2. 最终增量数据库备份
3. 恢复数据库到新服务器
4. 同步最新代码
5. 启动新服务器 PM2
6. 验证功能
7. 切换 DNS
8. 验证 DNS 生效

**阶段 4：观察（7-14 天）**
1. 保留旧服务器 7-14 天
2. 监控新服务器
3. 确认无问题后关闭旧服务器
