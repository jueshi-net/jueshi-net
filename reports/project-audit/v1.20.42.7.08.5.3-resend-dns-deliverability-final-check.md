### 3.3 DMARC 记录

**命令**:
```bash
dig +short TXT _dmarc.jueshi.net
```

**结果**:
```
"v=DMARC1; p=reject; sp=reject; adkim=s; aspf=s;"
```

**判断**: ⚠️ **已配置，但策略过于严格**

**当前配置**:
- `p=reject`: 主域策略为拒绝
- `sp=reject`: 子域策略为拒绝
- `adkim=s`: DKIM 对齐方式为严格（strict）
- `aspf=s`: SPF 对齐方式为严格（strict）

**问题分析**:
1. **SPF 未配置**: 当前 SPF 为 `-all`，所有邮件都会 SPF 失败
2. **DKIM 未配置**: DKIM CNAME 不存在，所有邮件都会 DKIM 失败
3. **DMARC 策略为 reject**: 会拒绝所有未通过 SPF 和 DKIM 验证的邮件
4. **严格对齐模式**: `adkim=s` 和 `aspf=s` 要求域名完全匹配，不允许子域

**与之前报告不一致的原因**:
- v1.20.42.7.08.5.1 报告称 "DMARC 未配置"
- v1.20.42.7.08.5.2 报告称 "DMARC 未配置"
- 本次复测发现 DMARC 已配置，且策略为 `p=reject`

**可能原因**:
1. DNS 传播延迟：之前检查时 DMARC 记录尚未传播
2. 检查时间差异：不同时间点的 DNS 缓存状态不同
3. 用户配置：用户可能在两次检查之间配置了 DMARC

**建议**:
- 测试阶段建议修改为：`v=DMARC1; p=quarantine; rua=mailto:dmarc@jueshi.net`
- 等待 SPF 和 DKIM 配置完成并验证通过后，再考虑使用 `p=reject`
- 如果继续使用 `p=reject`，必须确认 SPF 和 DKIM 均已正确配置

   - v1.20.42.7.08.5.2 中 DKIM 检查显示 "connection timed out"

   - 本地 DNS 缓存可能影响查询结果

- DMARC 记录已存在，策略为 `p=reject`
