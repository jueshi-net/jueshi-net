## Bot Runtime Root Cause

### 问题 1: 本地数据库不可用

```bash
psql -h 127.0.0.1 -p 5555 -U xixiong_user -d xixiong_staging -c "SELECT 1"
```

结果：`connection refused`

**原因**: 本地 PostgreSQL 未运行，SSH tunnel 虽然可以建立，但本地 Prisma CLI 无法解析 production DATABASE_URL。

### 问题 2: Bot 终端配置为 local

```yaml
terminal:
  backend: local
  cwd: /Users/chq/xixiong-saas
```

**原因**: Bot 的终端工具配置为本地执行，无法直接通过 SSH 在 production 服务器上执行命令。

### 问题 3: Production 服务器缺少脚本

```bash
ssh jueshi-new "ls /home/deploy/xixiong-saas/scripts/create-contentops-draft.mjs"
```

结果：`No such file or directory`

**原因**: Draft 创建脚本只在本地存在，未部署到 production。

**尝试**: 将 draft 创建脚本上传到 production，在 production 运行 bot

**结果**: ❌ 未实施

## 根本性环境限制

### 限制 1: 本地数据库不可用

本地 PostgreSQL 未运行，无法通过 127.0.0.1:5555 连接。

### 限制 2: Bot 无法连接 Production 数据库

Bot 终端配置为 `backend: local`，无法直接通过 SSH 在 production 服务器上执行命令。

### 限制 3: Hermes Agent 不支持 SSH 终端后端

无法修改 bot 配置让它通过 SSH 执行 production 命令。

### 限制 4: Production 服务器缺少 Draft 创建脚本

`scripts/create-contentops-draft.mjs` 只在本地存在，未部署到 production。

---

## 下一步建议

### 方案 1: 在 Production 部署 Bot（推荐）

1. 将 draft 创建脚本部署到 production
2. 在 production 配置 bot token 和环境变量
3. 在 production 运行 bot gateway
4. 从 Telegram 发送消息测试

**优点**: 真正的 Telegram flow E2E  
**缺点**: 需要部署，超出当前任务范围

### 方案 2: 修改 Hermes Agent 支持 SSH 终端

1. 修改 Hermes Agent 核心代码，支持 SSH 终端后端
2. 配置 contentops profile 使用 SSH 终端
3. 从 Telegram 发送消息测试

**优点**: 真正的 Telegram flow E2E  
**缺点**: 需要修改 Hermes Agent 核心代码，复杂度高

### 方案 3: 接受 CLI E2E 作为替代

1. 接受 CLI E2E 作为正式验证
2. 记录 Telegram bot E2E 被阻塞的原因
3. 在 SOP 中说明：Telegram bot E2E 需要在 production 环境验证

**优点**: 简单，不需要额外工作
