# v1.20.42.18.6.4.10-03 — Japan Tokyo City Query Fix

## Root Cause

Japan postal data stores prefecture in the `province` field as "Tokyo To". The API only searched `city` and `areaName` fields, missing the `province` field entirely.

## DB Audit

```sql
SELECT DISTINCT city, province FROM postal_codes WHERE "countryCode" = 'JP' AND province ILIKE 'Tokyo%' LIMIT 5;
-- Results: city=Aburadai province=Tokyo To, city=Adachi province=Tokyo To, etc.
```

## Fix

### City Alias Mapping
Added `CITY_ALIASES` dictionary to API:
- `tokyo` → ['Tokyo', 'Tokyo To', '東京都', 'Tokyo-to', 'Tokio']
- `osaka` → ['Osaka', 'Osaka Prefecture', '大阪府', 'Osaka-fu']
- `kyoto` → ['Kyoto', 'Kyoto Prefecture', '京都府', 'Kyoto-fu']
- `yokohama` → ['Yokohama', 'Kanagawa', '神奈川県']
- `nagoya` → ['Nagoya', 'Aichi', '愛知県']
- `sapporo` → ['Sapporo', 'Hokkaido', '北海道']
- `fukuoka` → ['Fukuoka', 'Fukuoka Prefecture', '福岡県']

### Search Fields
Search now includes `city`, `areaName`, `province`, AND `adminName1` for all queries.
