## 执行摘要

经过 v6.39-v6.47 共 9 个版本的 CSS/browser print 修复尝试，确认当前路线在 Mac mini / Safari / 10×10 多页标签场景下**无法作为精确输出主方案**。

**决策：**
1. **停止**继续修复 CSS print 作为主线
2. **新增**精确 PDF 导出功能作为正式标签输出路径
3. **保留**浏览器打印为"兼容模式"，不再宣称精确

### v6.47: 诊断结论

**PRINT_PIPELINE_APP_RENDERER_CONFIRMED_BROKEN**

诊断发现以下根本问题：

#### 1. px 浮点单位不适合 Safari 精确打印
```typescript
// 当前代码使用 px 浮点单位
element.x = 37.795275591  // 10mm in px
element.y = 75.590551182  // 20mm in px
```

**问题：**
- Safari 打印引擎对浮点 px 坐标处理不稳定
- 不同 Safari 版本渲染结果不一致
- 无法保证精确的物理尺寸输出

#### 2. iframe 隔离是风险源
```typescript
// 当前使用 iframe 隔离打印内容
const iframe = document.createElement('iframe');
iframe.contentDocument.body.innerHTML = printHtml;
iframe.contentWindow.print();
```

**问题：**
- iframe 与主文档样式隔离不完整
- Safari 对 iframe 打印有特殊限制
- 跨 iframe 的字体加载不稳定

#### 3. 外部样式注入导致不可预测行为
```typescript
// 注入 Tailwind CSS 和自定义样式
const style = document.createElement('style');
style.textContent = tailwindCss + customPrintCss;
document.head.appendChild(style);
```

**问题：**
- Tailwind CSS v4 使用 lab()/oklch() 颜色函数，Safari 打印支持不完整
- 样式优先级冲突导致布局错乱
- 无法保证打印输出与设计一致

#### 4. 纯 HTML MRE 与 App 差异显著

**纯 HTML MRE 测试结果：**
```html
<!-- 简单的 10×10 标签，纯 HTML + CSS -->
<div style="width: 100mm; height: 100mm; border: 1px solid black;">
  标签内容
</div>
```
✅ Safari 打印正常，尺寸准确

**App 打印结果：**
```typescript
// 相同的 10×10 设计，通过 App 打印
<CanvasElement x={37.79} y={75.59} width={377.95} height={377.95} />
```
❌ Safari 打印失败，大量空白，坐标偏移

**结论：** App 的打印渲染器引入了额外复杂性（React 状态、动态样式、iframe 隔离），导致 Safari 打印引擎行为不可预测。

## 技术评估

### 外部技术建议

1. **设计态和输出态分离**
   - 编辑器使用 px 坐标（设计态）
   - 输出使用物理尺寸（输出态）
   - 两者通过坐标转换层连接

2. **模板数据是唯一真值**
   - 不依赖 DOM 克隆
   - 不依赖 getBoundingClientRect
   - 直接从 template JSON 生成输出

3. **精确标签输出应走 PDF**
   - PDF 支持精确物理尺寸
   - PDF 支持多页
   - PDF 支持中文字体嵌入
   - PDF 不依赖浏览器打印引擎

4. **Safari/macOS 下不要依赖 @page + window.print**
   - Safari 打印引擎对 @page 支持不完整
   - macOS 打印预览与实际输出可能不一致
   - 无法保证跨浏览器一致性

## 决策：PDF Output MVP

### 技术选型

**选择:** `@react-pdf/renderer`

**原因:**
1. React/Next 技术栈接入成本低
2. 支持 Document/Page/View/Text 组件
3. 支持多页（repeat 模式）
4. 支持绝对定位（mm 坐标）
5. 支持中文字体嵌入
6. 不依赖浏览器打印引擎

**备选方案:**
- `pdf-lib`: 如果 @react-pdf/renderer 因中文/表格/构建问题阻塞
- **不使用:** `html2canvas + jsPDF`（截图 PDF，不精确）

### 架构设计

```
src/lib/template-studio/pdf/
├── paper-spec.ts        # 纸张规格（10×10, 10×15, A4）
├── coordinate.ts        # 坐标转换（px → mm → pt）
├── token-resolver.ts    # Token 解析（[company.name], [sequence]）
├── render-label-pdf.tsx # PDF 渲染主逻辑
└── pdf-types.ts         # TypeScript 类型定义
```

**核心原则:**
1. **数据驱动** — 从 canvas state / template JSON 读取数据
2. **不读取 DOM** — 不克隆 DOM，不使用 getBoundingClientRect
3. **不使用 iframe** — 直接生成 PDF，不通过浏览器打印
4. **不注入样式** — 不使用 Tailwind CSS，不注入外部样式
5. **不使用 window.print** — 不依赖 @page，不依赖 Safari 打印引擎

### 功能范围

**MVP 必须支持:**
- ✅ text 文本元素
- ✅ sequence / package sequence（1/N, 2/N, ...）
- ✅ company-info 组合块
- ✅ product table 商品表格
- ✅ 普通绑定文本
- ✅ 中文字体（Noto Sans SC）
- ✅ 多页支持（packageCount=11 → 11 页 PDF）
- ✅ 精确尺寸（10×10 → 100mm × 100mm）

**MVP 不新增:**
- ❌ Logo 块
- ❌ 二维码
- ❌ 条形码
- ❌ 会员权限
- ❌ 批量 PNG ZIP

### 坐标转换

**当前状态:**
- 编辑器内部使用 mm 坐标（已迁移）
- PDF 使用 pt 坐标（1mm = 2.83465pt）

**转换逻辑:**
```typescript
// coordinate.ts
export function mmToPt(mm: number): number {
  return mm * 2.83465;
}

export function normalizeElementForPdf(
  element: CanvasElement,
  paperWidthMm: number,
  paperHeightMm: number
): NormalizedElement {
  // 如果元素已经是 mm，直接使用
  // 如果元素是 px，需要转换
  return {
    x: mmToPt(element.x),
    y: mmToPt(element.y),
    width: mmToPt(element.width),
    height: mmToPt(element.height),
    fontSize: element.style.fontSize, // pt
  };
}
```

**要求:**
- 所有 px/mm/pt 换算集中在 coordinate.ts
- 不允许到处散落魔法数字（3.7795275591, 2.83465）
- 不允许把 screen px 当 PDF pt
- 坐标转换必须有单元测试或审计验证
