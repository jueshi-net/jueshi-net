## 失败 case 详细分析

### Case ID
TS-CANVAS-SAVE-RESTORE

### 名称
保存恢复功能

### Priority
P1

### 错误信息
```
page.waitForFunction: Timeout 30000ms exceeded.
```

### 审计脚本实现（第 257-273 行）

```typescript
await runAudit(
  'TS-CANVAS-SAVE-RESTORE',
  '保存恢复功能',
  async () => {
    // Click save button
    await page.click('[data-testid="canvas-save-button"]');
    
    // Wait for save status
    await page.waitForFunction(() => {
      const btn = document.querySelector('[data-testid="canvas-save-button"]');
      return btn?.textContent?.includes('已保存');
    }, { timeout: 5000 });
    
    return 'Save successful';
  }
);
```

### 根因分析

1. **审计脚本未登录**（第 64 行注释）:
   ```typescript
   // Note: Canvas editor accessible without login for MVP
   await navigateToCanvas(page);
   ```

2. **保存功能需要认证**:
   - 点击保存按钮后调用 `/api/template-studio/templates` API
   - 该 API 需要 NextAuth session
   - 未登录状态下 API 返回 401 Unauthorized

3. **按钮状态不会变化**:
   - 代码逻辑：`setSaveStatus("saving")` → API 调用 → `setSaveStatus("saved")` 或 `setSaveStatus("error")`
   - API 失败后状态变为 "error"，按钮文本显示"保存"（不是"已保存"）
   - `waitForFunction` 等待"已保存"超时

### 真实功能验证

### 结论

**这是审计脚本问题，不是真实功能问题**。

原因：
1. Touch/Sequence 审计脚本未登录
2. 保存 API 需要认证
3. 未登录状态下保存失败是预期行为
4. 保存功能已在 Canvas Batch Audit（登录状态）中验证通过

### 修复方案

**方案 A**: 在 Touch/Sequence 审计中添加登录  
- 优点：完整验证保存流程
- 缺点：增加审计复杂度，与核心目标（触控/序号）无关

**方案 B**: 修改断言，验证按钮存在且可点击  
- 优点：简单，聚焦核心目标
- 缺点：不验证完整保存流程

**方案 C**: 验证保存按钮点击后状态变化（任何最终状态）  
- 优点：验证按钮交互
- 缺点：未登录状态下只能验证到 "error" 状态

**推荐**: 方案 B  
理由：
1. Touch/Sequence 审计的核心目标是验证触控和序号功能
2. 保存功能已在 Canvas Batch Audit 中完整验证
3. 避免重复验证，保持审计脚本简洁
