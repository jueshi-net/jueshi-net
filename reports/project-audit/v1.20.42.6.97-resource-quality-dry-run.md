## 二、qualityScore = 0 的资源分析

### 2.1 统计信息

- **数量**: 89 条
- **占比**: 9.6%
- **严重程度**: 中

### 2.2 影响分析

**前台影响**:

| ... | ... | ... | ... |

**注意**: 完整列表需要通过数据库查询获取，本报告仅展示样例。

### 2.4 修复建议

**方案 A: 批量设置默认质量评分（推荐）**

```sql
UPDATE resources
SET quality_score = 50
WHERE quality_score = 0;
```

**影响**:
- 89 条资源的 qualityScore 从 0 更新为 50
- 这些资源会排在中等位置
- 后续可以通过死链检测自动调整评分

**风险**: 低（仅更新一个字段）

**验收标准**:
- qualityScore = 0 的数量: 0
- qualityScore = 50 的数量: 89+
- 总资源数: 929（不变）

**方案 B: 基于 sourceType 设置质量评分**

```sql
UPDATE resources
SET quality_score = CASE
  WHEN sourceType = 'official' THEN 90
  WHEN sourceType = 'third-party' THEN 70
  WHEN sourceType = 'internal' THEN 80
  ELSE 50
END
WHERE quality_score = 0;
```

**影响**:
- official 资源: 90 分
- third-party 资源: 70 分
- internal 资源: 80 分
- 其他: 50 分

**风险**: 低（仅更新一个字段）

**推荐**: 方案 B（更精细）

## 三、缺 favicon 的资源分析

### 3.1 统计信息

- **数量**: 304 条
- **占比**: 32.7%
- **严重程度**: 中

### 3.2 影响分析

**前台影响**:
- ⚠️ 资源卡片显示默认图标，视觉体验差
- ⚠️ 用户难以快速识别网站

**后台影响**:
- ⚠️ 管理员难以识别资源

### 3.3 修复建议

**方案 A: 自动抓取 favicon（推荐）**

**实现方式**:
1. 编写脚本遍历所有缺 favicon 的资源
2. 从 URL 提取域名
3. 使用 Google Favicon API 或其他服务抓取 favicon
4. 更新 resources.favicon 字段

**脚本示例**:
```javascript
const resources = await prisma.resource.findMany({
  where: { favicon: null }
});

for (const resource of resources) {
  try {
    const url = new URL(resource.url);
    const domain = url.hostname;
    const faviconUrl = `https://www.google.com/s2/favicons?domain=${domain}&sz=64`;
    
    await prisma.resource.update({
      where: { id: resource.id },
      data: { favicon: faviconUrl }
    });
  } catch (error) {
    console.error(`Failed to fetch favicon for ${resource.url}:`, error);
  }
}
```

**影响**:
- 304 条资源的 favicon 字段被更新
- 前台显示网站图标，视觉体验提升

**风险**: 中（需要网络请求，可能失败）

**验收标准**:
- 缺 favicon 的数量: < 50（部分网站可能没有 favicon）
- 总资源数: 929（不变）

**方案 B: 手动添加 favicon**

**实现方式**:
1. 后台管理界面添加 favicon 编辑功能
2. 管理员手动上传或粘贴 favicon URL

**影响**:
- 需要人工操作，耗时较长

**推荐**: 方案 A（自动化）

## 四、缺 iconUrl 的资源分析

### 4.1 统计信息

- **数量**: 927 条
- **占比**: 99.8%
- **严重程度**: 高

### 4.2 影响分析

**前台影响**:
- ❌ 几乎所有资源都显示默认图标
- ❌ 视觉体验差

**后台影响**:
- ❌ 管理员难以识别资源

### 4.3 iconUrl vs favicon 的区别

| 字段 | 说明 | 优先级 |
|------|------|--------|
| favicon | 网站自动提供的图标 | 低优先级 |
| iconUrl | 管理员自定义的图标 | 高优先级 |

**前台渲染逻辑**:
```typescript
const logoSrc = resource.iconUrl || resource.favicon || null;
```

**结论**: iconUrl 优先级高于 favicon，但 99.8% 的资源都缺 iconUrl

### 4.4 修复建议

**方案 A: 将 favicon 复制到 iconUrl（推荐）**

```sql
UPDATE resources
SET icon_url = favicon
WHERE icon_url IS NULL
  AND favicon IS NOT NULL;
```

**影响**:
- 约 625 条资源的 iconUrl 被更新（929 - 304 = 625）
- 前台显示网站图标

**风险**: 低（仅更新一个字段）

**验收标准**:
- 缺 iconUrl 的数量: 304（与缺 favicon 的数量一致）
- 总资源数: 929（不变）

**方案 B: 批量上传自定义图标**

**实现方式**:
1. 后台管理界面添加批量上传功能
2. 管理员上传自定义图标
3. 更新 iconUrl 字段

**影响**:
- 需要人工操作，耗时较长
- 视觉体验更好

**推荐**: 方案 A（快速修复）+ 方案 B（长期优化）
