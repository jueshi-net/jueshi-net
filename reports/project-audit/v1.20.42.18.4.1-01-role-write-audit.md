### ❌ 未修复的代码（根因）

#### 3. `src/lib/invite-rewards.ts` - **根因**

**状态：** ❌ 未修复

**代码（第 246-252 行）：**
```typescript
await prisma.user.update({
  where: { id: userId },
  data: {
    memberUntil: newMemberUntil,
    role: 'member', // 确保角色为 member  ❌ 问题所在
  },
});
```

**问题：**
- 当邀请奖励发放会员天数（MEMBER_DAYS）时
- 会把用户的 role 强制改为 'member'
- 即使用户原本是 admin，也会变成 member
- 这就是为什么 9833416@qq.com 在邀请新用户后变成了会员

**根因确认：**
- 用户反馈：9833416@qq.com 邀请了一个新用户后变成会员
- 代码路径：邀请注册 → grantInviteRewards → executeRewardGrant → grantMemberDays
- grantMemberDays 函数在第 250 行强制设置 `role: 'member'`
- 这覆盖了 9833416@qq.com 的 admin role

**修复方案：**
- 移除 `role: 'member'` 这一行
- 只更新 memberUntil，不修改 role
- 会员身份应该通过 memberUntil 判断，而不是 role

### 问题链路

```
用户邀请新用户

  ↓

  ↓
```

### 修复目标

1. **移除 `role: 'member'`**

   - 不修改 role

2. **添加保护逻辑**

   - 或者完全不修改 role，只通过 memberUntil 判断会员

3. **添加回归测试**
   - admin inviter invites user, inviter remains admin
   - normal inviter invites user, inviter remains user
   - invite reward does not write role=member

### 方案 B：添加保护逻辑

**修改 `src/lib/invite-rewards.ts`：**

```typescript
const currentUser = await prisma.user.findUnique({
  where: { id: userId },
  select: { role: true },
});

// 只有非 admin 用户才修改 role
const shouldUpdateRole = currentUser?.role !== 'admin';

await prisma.user.update({
  where: { id: userId },
  data: {
    memberUntil: newMemberUntil,
    ...(shouldUpdateRole && { role: 'member' }),
  },
});
```

**优点：**
- 保护 admin 用户
- 更灵活

**缺点：**
- 改动较大
- 不符合"role 只表示权限"的原则
