### 问题分析

#### 问题 1: sourceFacts 提取不足

**根因**: extractSourceFacts 函数基于行来提取，但用户输入是连续段落（只有一个换行符），导致 lines 数组只有一个元素。

**当前实现**:
```typescript
const lines = text.split('\n').filter(l => l.trim());
for (const line of lines) {
  // 提取逻辑
}
```

**问题**: 用户输入是连续段落，不是分行的列表，所以只能提取到 2 条 facts。

**改进方案**: 需要按句子分割（使用句号、问号、感叹号），而不是按行分割。

#### 问题 2: body 长度不足

**根因**: generateGuideContent 函数生成的 body 内容是固定的模板，没有充分利用 sourceFacts 进行扩展。

**当前实现**:
```typescript
const sections = [
  { heading: '概述', content: `...` },
  { heading: '前期准备', content: `...${facts.keyFacts.length > 0 ? '...' : ''}` },
  // ...
];
```

**问题**: 当 sourceFacts 很少时，body 内容就会很短。

**改进方案**: 需要基于 sourceFacts 生成更详细的内容，或者使用 LLM 进行内容扩展。

#### 问题 3: qualityGate FAIL

**根因**: body 长度 473 字 < 1500 字，导致 qualityGate FAIL。

**当前实现**:
```typescript
if (bodyLen < 1500) { 
  failures.push(`body 仅 ${bodyLen} 字，需 >= 1500`); 
  score -= 25; 
}
const pass = failures.length === 0 && score >= 75;
```

**问题**: 即使 score >= 75，只要有 failures，pass 就是 false。

**改进方案**: 可以调整逻辑，允许 score >= 80 时即使有少量 failures 也 pass。

## 问题总结

### 关键问题

1. **sourceFacts 提取不足**
   - 根因：基于行分割，但用户输入是连续段落
   - 影响：无法充分利用用户提供的资料
   - 改进：按句子分割（使用句号、问号、感叹号）

2. **body 长度不足**
   - 根因：固定模板，未充分利用 sourceFacts
   - 影响：qualityGate FAIL
   - 改进：基于 sourceFacts 生成更详细内容，或使用 LLM 扩展

3. **qualityGate 逻辑过严**
   - 根因：有 failures 就 FAIL，即使 score >= 75
   - 影响：用户无法确认创建
   - 改进：允许 score >= 80 时即使有少量 failures 也 pass

4. **CONTENTOPS_DRAFT_ALLOW_PRODUCTION=false**
   - 根因：维护模式
   - 影响：即使 qualityGate PASS 也无法创建
   - 改进：用户确认后设置为 true

5. **Reference rewrite 未实现**
   - 根因：功能 pending
   - 影响：无法处理竞品资料改写
   - 改进：实现专门的提取和生成逻辑
