## 二、Schema 根因分析

### 问题根因

`validateTemplateConfig()` 在 `src/lib/template-studio/template-schema.ts` 中仅针对结构化模板设计，要求 `id`、`toolKey`、`fields`、`columns`、`style` 字段。但 Canvas 模板的数据结构完全不同：

- Canvas: `{ mode: "canvas", name, paper, elements: [], grid, batch }`
- Structured: `{ id, toolKey, name, fields: [], columns: [], style: {} }`

当 Canvas 模板保存时，服务器端验证拒绝整个 payload，报错："Missing or invalid id, Missing or invalid toolKey, fields must be an array, columns must be an array, Missing style config"。

### Schema Normalizer 说明

新增 `validateCanvasTemplateConfig()` 函数：
1. 检测 `mode === "canvas"` 时走 canvas 专用验证路径
2. 验证 `name`、`paper`、`elements`（必须为数组）
3. 对每个 element 自动修复缺失的 `id`（生成 `el-{timestamp}-{idx}-{random}`）
4. 对每个 element 自动修复缺失的 `style`（填充默认值）
5. 验证 `grid` 和 `batch`（如果存在则为对象）
6. 不要求 `fields`/`columns`/`toolKey`/`id`（这些是结构化模板专用字段）

## 三、修复内容

### PHASE 6 (Responsive Layout)
- 添加全局 `overscrollBehavior: "none"` 防止 iPad 下拉刷新
- 编辑器根容器添加 `overflow-x-hidden` + `overscroll-contain` 防止横向溢出
- 拖动/resize 时 `touchAction: "none"` 防止页面跟随滚动

### PHASE 7 (Multi-page Sequence)
- 序号元素现在是真实 canvas element（不是硬编码角标）
- 多页模式第 1 页（pageIndex=0）可选择、可拖动、可 resize
- 序号元素应用 `fontFamily`/`fontSize`/`fontWeight`/`color` 样式
- 取消显示序号时，所有页的序号元素隐藏（`canvas-sequence-hidden` marker）
- 勾选显示序号时自动创建序号元素（如不存在）
- data-testid: `canvas-sequence-element`、`canvas-sequence-selected`、`canvas-sequence-resize-handle`、`canvas-page-1-sequence`、`canvas-page-10-sequence`、`canvas-sequence-hidden`

### PHASE 8 (Grid & Snap)
- 网格线颜色从 `#e5e7eb` 改为 `#9ca3af`，线宽从 `0.5` 改为 `1`（更可见）
- data-testid 从 `canvas-grid-toggle` 改为 `canvas-show-grid-toggle`
- PNG 导出时隐藏网格 overlay、resize handle、选中框
- 吸附逻辑已存在且正常工作（`snapToGrid` 在 `handlePointerMove` 中）

### PHASE 9 (Font Selection)
- 字体标签更新：系统字体、无衬线、衬线、等宽
- 文本元素完整应用 `fontFamily`/`fontSize`/`fontWeight`/`color`
- 字段元素也应用字体样式

### PHASE 10 (Undo/Redo)
- 撤销/重做一次一步已验证正常
- 无代码变更需要（回归保护通过）
