# v1.20.42.18.6.4.11-02 — Postal Taskchain 404 Fix

## Root Cause

`handleSelectTaskChain` redirected to `/workspace/task-chains/${taskChain.id}` — a route that does NOT exist. The only valid dynamic route is `/workspace/task-chains/shipping/[id]`.

## Click Flow Audit

### Flow 1: Direct Join (`joinShippingTaskChain`)
- Button: "加入任务链" (line 1097)
- Not logged in → `/login?callbackUrl=...` ✅
- Logged in → `POST /api/task-chains` → redirect to `/workspace/task-chains/shipping/${id}` ✅

### Flow 2: Dialog Join (`openTaskChainDialog` → `TaskChainSelectDialog`)
- Button: "加入任务链" (line 1097)
- Not logged in → `/login?callbackUrl=...` ✅
- Logged in → Dialog opens → User selects/creates chain:
  - Select existing: `handleSelectTaskChain` → `router.push('/workspace/task-chains/shipping/${id}')` ✅ (FIXED)
  - Create new: `handleCreateNewTaskChain` → `onSelect(newChain)` → `handleSelectTaskChain` → same redirect ✅

### Flow 3: TaskChainSelectDialog confirm button
- `handleCreateNew()` → calls `onCreateNew(title)` → `handleCreateNewTaskChain` → `createTaskChain()` → API POST
- On success → `onSelect(newChain)` → `handleSelectTaskChain` → redirect ✅

## Fix

```typescript
// BEFORE (404):
router.push(`/workspace/task-chains/${taskChain.id}`);

// AFTER (200):
router.push(`/workspace/task-chains/shipping/${taskChain.id}`);
```

## Verification

- `/workspace/task-chains/shipping/new` → HTTP 200 ✅
- `/workspace/task-chains/shipping/[id]` → exists as dynamic route ✅
- All `/auth/signin` references replaced with `/login` (fixed in v18.6.4.10) ✅
- Login flow: unauthenticated → `/login?callbackUrl=...` (no 404) ✅
