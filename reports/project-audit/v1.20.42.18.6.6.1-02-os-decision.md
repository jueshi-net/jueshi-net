# OS Decision: Debian 13 vs Ubuntu 24.04 LTS — v1.20.42.18.6.6.1

## 当前生产环境

- OS: Ubuntu 24.04.4 LTS
- PostgreSQL: 16.14 (Ubuntu)
- Nginx: 1.24.0 (Ubuntu)
- Node.js: v22.22.2
- PM2: fork_mode

## 方案 A: 重装 Ubuntu 24.04 LTS

### 优点
- 与当前生产环境**完全一致**，迁移脚本零适配
- 包名、服务名、配置路径统一
- apt 源一致，版本一致
- 运维文档无需分叉
- 今天内迁移风险最低

### 缺点
- 需要重装时间（~15-30 分钟）
- 重装会清空新服务器现有内容
- 依赖服务商是否有 Ubuntu 24.04 镜像

### 适用条件
新服务器刚开通、尚未放数据、重装方便。

## 方案 B: 保留 Debian 13 (trixie)

### 优点
- 不用重装，节省时间
- Debian 稳定性好
- 能运行 Node/Next/PostgreSQL/Nginx/PM2

### 风险
- **包版本差异**: Debian 13 的 PostgreSQL 可能是 17.x，与生产 16.x 不同
- **配置路径差异**: 部分 Nginx/systemd 配置可能不同
- **脚本适配**: deploy-safe.sh、health-check.sh 等假设 Ubuntu，需验证
- **排错成本高**: 迁移时遇到问题需要额外排查 OS 差异
- **文档分叉**: 运维文档需要同时维护两套

### 适用条件
不方便重装，或 Debian 已确认干净且 bootstrap preflight 通过。

## 最终推荐

**优先级 1: 重装 Ubuntu 24.04 LTS**（如果新服务器尚未承载任何数据）

**优先级 2: 保留 Debian 13**（如果不方便重装，但必须先跑 Debian bootstrap preflight checklist）

### 推荐理由

当前生产环境所有脚本、Nginx 配置、PM2 ecosystem、cron jobs 均基于 Ubuntu 24.04 编写和验证。迁移本身已有足够风险，不应该再叠加 OS 差异风险。如果新服务器是全新的（未放数据），重装 Ubuntu 的 15-30 分钟成本远低于 Debian 差异带来的排错时间。
