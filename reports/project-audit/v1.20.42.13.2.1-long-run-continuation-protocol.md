# v1.20.42.13.2.1 长链路续杯记录规范

**创建时间**: 2026-06-20  
**目的**: 规范后续所有长链路任务的执行记录，防止夸大和虚假报告

---

## 一、强制记录字段

所有长链路任务（超过 1 小时或超过 3 个阶段）的报告必须包含以下字段：

```yaml
# 执行元数据
runId: <UUID 或版本号>
startAt: <ISO 8601 timestamp>
endAt: <ISO 8601 timestamp>
totalDuration: <实际执行时长，格式: Xh Ym Zs>

# 续杯机制
continuationCount: <数字 或 "unavailable in current execution environment">
continuationEvidence:
  - type: <git commit / context window reset / explicit continuation marker>
    timestamp: <ISO 8601>
    evidence: <具体证据描述>

# Checkpoint 列表
checkpointList:
  - phase: <阶段名称>
    startAt: <ISO 8601>
    endAt: <ISO 8601>
    commitHash: <git commit hash>
    filesChanged:
      - <file path>
    buildSucceeded: <true/false>
    deploySucceeded: <true/false>

# 阶段时间线
phaseStart: <第一阶段开始时间>
phaseEnd: <最后阶段结束时间>

# 每个阶段的 commit
commitPerPhase:
  - phase: <阶段名称>
    commits:
      - hash: <commit hash>
        message: <commit message>
        timestamp: <ISO 8601>

# 构建和部署统计
buildCount: <总构建次数>
deployCount: <总部署次数>
migrationCount: <总 migration 数量>

# 错误和限流
429Count: <429 错误次数>
rateLimitWaits:
  - timestamp: <ISO 8601>
    duration: <等待时长>
    reason: <原因>
failedCommands:
  - command: <失败命令>
    timestamp: <ISO 8601>
    error: <错误信息>
    resolved: <true/false>

# 跳过阶段
skippedStagesWithReason:
  - stage: <阶段名称>
    reason: <跳过原因>
    impact: <影响评估>

# 用户操作
userActionRequired:
  - action: <需要的用户操作>
    reason: <原因>
    priority: <P0/P1/P2>

# 问题清单
P0Issues:
  - issue: <问题描述>
    phase: <相关阶段>
    status: <open/resolved>
P1Issues: []
P2Issues: []
```

---

## 二、续杯次数记录规则

### 情况 1: 可以获取续杯次数

如果系统提供续杯计数 API 或日志：
```yaml
continuationCount: 3
continuationEvidence:
  - type: context window reset
    timestamp: 2026-06-20T10:00:00Z
    evidence: "Context compaction triggered, resumed from checkpoint"
  - type: git commit
    timestamp: 2026-06-20T10:05:00Z
    evidence: "New commit after context reset: abc1234"
```

### 情况 2: 无法获取续杯次数

如果系统不提供续杯计数：
```yaml
continuationCount: unavailable in current execution environment
continuationEvidence:
  - type: git commit timeline
    timestamp: 2026-06-20T08:14:00Z
    evidence: "All commits within 23 minutes, no evidence of context reset"
```

**禁止**:
- ❌ 写"自动续杯 N 次"（除非有真实证据）
- ❌ 写"长时间执行"（必须给出具体时长）
- ❌ 把单次长会话伪装成多次续杯

## 三、完成度评估标准

每个阶段的完成度必须按以下标准评估：

| 完成度 | 标准 |
|--------|------|
| 100% | 功能完成 + 前端 UI + 真实测试 + 部署验证 |
| 70% | 功能完成 + 前端 UI + 部署，但未真实测试 |
| 50% | API/后端完成，前端未完成或未集成 |
| 30% | 字段/骨架/脚本完成，无完整功能 |
| 10% | 仅报告/审计，无代码变更 |
| 0% | 未开始 |

**禁止**:
- ❌ 仅 API 完成就声称"100% 完成"
- ❌ 仅 URL 200 就声称"功能验证通过"
- ❌ 仅字段存在就声称"功能可用"

## 五、审计检查清单

每次长链路任务完成后，必须自检：

- [ ] 执行时长是否真实（对比 git 时间戳）
- [ ] 续杯次数是否有证据
- [ ] 每个阶段的完成度是否准确
- [ ] 是否列出了所有缺口
- [ ] 是否夸大了完成度
- [ ] 是否诚实列出了未完成项
- [ ] 是否提供了真实测试证据

---

## 六、违规处理

如果发现报告存在夸大或虚假：

1. **立即创建审计报告**（如 v1.20.42.13.2.1）
2. **列出所有证据缺口**
3. **给出真实完成度评估**
4. **更新后续任务规范**
5. **不得继续基于虚假报告推进**
