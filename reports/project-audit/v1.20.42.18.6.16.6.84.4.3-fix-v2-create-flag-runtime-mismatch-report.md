**执行时间**: 2026-07-04 14:30 UTC

## 执行摘要

修复了 ContentOps V2 的 create flag 运行时不一致问题。根因是 wrapper 脚本硬编码了 `CONTENTOPS_DRAFT_ALLOW_PRODUCTION=false`，覆盖了 .env.contentops 中的配置。

---

## PHASE 1 — 审计 createDraftEnabled 来源

### 问题根因

**根因**: `start-contentops-bot-wrapper.sh` 第24行硬编码了：

```bash
export CONTENTOPS_DRAFT_ALLOW_PRODUCTION=false
```

这会覆盖 `.env.contentops` 中设置的值。

### 配置来源分析

| 来源 | 值 | 是否生效 |
|------|-----|---------|
| `.env.contentops` | `CONTENTOPS_DRAFT_ALLOW_PRODUCTION=true` | ❌ 被覆盖 |
| `start-contentops-bot-wrapper.sh` | `export CONTENTOPS_DRAFT_ALLOW_PRODUCTION=false` | ✅ 生效 |
| Bot 启动时读取 | `process.env.CONTENTOPS_DRAFT_ALLOW_PRODUCTION` | false |
| dry-run 阶段 | `CONFIG.allowProduction` | false |
| confirm-create 阶段 | `CONFIG.allowProduction` | false |

### 一致性检查

```
dryRunCreateEnabledSource: CONFIG.allowProduction (from process.env)
confirmCreateEnabledSource: CONFIG.allowProduction (from process.env)
preflightCreateEnabledSource: CONFIG.allowProduction (from process.env)
pm2RuntimeValue: false (被 wrapper 覆盖)
envFileValue: true (.env.contentops)
sourcesConsistent: false (wrapper 覆盖了 .env)
```

## PHASE 3 — 修复 dry-run 行为

### 修复内容

**文件**: `scripts/contentops/contentops-telegram-bot.ts`

**函数**: `formatDryRunV2`

**修改前**:
```typescript
if (pending.qualityGate.pass) {
  msg += `请回复:\n`;
  msg += `  ✅ "确认创建" — 创建 draft\n`;
  // ...
}
```

**修改后**:
```typescript
const createEnabled = CONFIG.allowProduction;

if (pending.qualityGate.pass && createEnabled) {
  msg += `请回复:\n`;
  msg += `  ✅ "确认创建" — 创建 draft\n`;
  // ...
} else if (pending.qualityGate.pass && !createEnabled) {
  msg += `🔧 当前创建通道处于维护模式，只能预览 dry-run，暂不能创建 draft。\n\n`;
  msg += `请回复:\n`;
  msg += `  ✏️ "修改标题为 XXX" — 调整标题\n`;
  // ...
}
```

### 效果

- 当 `createDraftEnabled=false` 时，不显示"确认创建"选项
- 显示维护模式提示
- 避免用户盲测
