## 问题根因

### 根因 1: Telegram Polling 位置错误

- **期望**: 本地 Mac 运行 Telegram polling
- **实际**: 服务器运行 Telegram polling
- **影响**: 服务器上的 Bot 无法调用本地 Hermes Agent

### 根因 2: LOCAL_HERMES_ENABLED 配置错误

- **期望**: 调用 Hermes Agent 的 Bot 应该启用 LOCAL_HERMES_ENABLED=true
- **实际**: 服务器上的 Bot 禁用 LOCAL_HERMES_ENABLED=false
- **影响**: 服务器上的 Bot 使用 rule-based processing，不调用 Hermes Agent

### 根因 3: 本地 Bot 未启动

- **期望**: 本地 Mac 运行 Bot 并处理 Telegram 消息
- **实际**: 本地 Mac 没有 Bot 在运行
- **影响**: 本地测试通过，但无法接收真实 Telegram 消息

---

## 解决方案

### 方案 1: 在本地 Mac 启动 Bot（推荐）

**步骤**:
1. 停止服务器上的 Bot
2. 在本地 Mac 启动 Bot
3. 配置本地 Bot 通过 SSH/API 创建 production draft

**优点**:
- 符合 singlePollerLocation=local_mac 要求
- 本地 Bot 可以调用本地 Hermes Agent
- 架构清晰

**缺点**:
- 本地 Mac 需要保持运行
- 本地 Mac 需要 SSH 访问生产服务器
- 网络延迟可能影响用户体验

### 方案 2: 在服务器上启用 Hermes Agent

**步骤**:
1. 在服务器上安装 Hermes Agent
2. 配置服务器上的 LOCAL_HERMES_ENABLED=true
3. 让服务器上的 Bot 调用服务器上的 Hermes Agent

**优点**:
- 不需要改变 Telegram polling 位置
- 生产环境更稳定

**缺点**:
- 违反 singlePollerLocation=local_mac 要求
- 需要在服务器上安装额外的软件
- 之前已经删除了服务器上的 Hermes Worker

### 方案 3: 混合架构（不推荐）

**步骤**:
1. 服务器上的 Bot 接收 Telegram 消息
2. 服务器上的 Bot 通过 SSH 调用本地 Mac 的 Hermes Agent
3. 本地 Mac 的 Hermes Agent 返回结果
4. 服务器上的 Bot 创建 draft

**优点**:
- 保持 Telegram polling 在服务器上
- 可以使用本地 Mac 的 Hermes Agent

**缺点**:
- 架构复杂
- SSH 调用可能不稳定
- 网络延迟影响性能
