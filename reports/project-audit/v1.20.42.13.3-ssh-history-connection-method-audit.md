## 九、判断：连接方式问题还是服务器端拒绝

### 9.1 判断依据

1. **历史连接方式与当前尝试完全一致**
   - 用户、主机、端口、密钥都相同
   - 没有使用 SSH alias、ProxyJump 等特殊配置

2. **网络层正常**
   - Ping 成功，延迟 < 1ms
   - 端口 22 开放，TCP 连接可建立

3. **SSH 协议层异常**
   - 在密钥交换阶段被服务器拒绝
   - 未到达认证阶段

4. **多次尝试结果一致**
   - 3 次验证都失败
   - 错误完全相同

### 9.2 判断结论

**❌ 不是连接方式问题**  
**✅ 是服务器端拒绝**

**根因**: 服务器在 SSH 协议握手阶段主动断开连接，问题在服务器端配置或状态。

### 9.3 可能的服务器端原因

根据错误特征，可能的原因按优先级排序：

1. **fail2ban 封禁** (最可能)
   - IP 被 fail2ban 临时封禁
   - 但端口仍然开放（应用层阻止）

2. **sshd MaxStartups 限制**
   - 并发连接数达到上限
   - 新连接被拒绝

3. **sshd_config 访问控制**
   - `AllowUsers` / `DenyUsers` 配置
   - `Match Address` 规则
   - 但这种情况通常在认证后拒绝

4. **云安全组/防火墙**
   - 但端口测试成功，不太可能

5. **sshd 服务异常**
   - 服务在运行但配置错误
   - 资源不足

6. **磁盘/资源问题**
   - 磁盘满导致无法写入
   - 内存不足

## 十、建议用户下一步操作

### 10.1 优先级 1：通过云控制台访问 VPS

由于 SSH 无法连接，**必须通过云服务商控制台**访问服务器。

**步骤**:

1. **登录云服务商控制台**
   - 阿里云 / 腾讯云 / AWS / 其他
   - 找到 VPS 实例 (192.129.155.149)

2. **使用 VNC 或 Web Terminal**
   - 大多数云服务商提供浏览器内的终端
   - 不需要 SSH 连接

3. **执行诊断命令**

```bash
# 一、确认 sshd 服务状态
sudo systemctl status sshd --no-pager
sudo journalctl -u sshd -n 100 --no-pager
sudo ss -lntp | grep ':22'

# 二、检查 SSH 配置
sudo sshd -t
sudo grep -nE '^(Port|PermitRootLogin|PasswordAuthentication|PubkeyAuthentication|AllowUsers|DenyUsers|AllowGroups|DenyGroups|Match|MaxStartups|LoginGraceTime|UsePAM|AllowTcpForwarding)' /etc/ssh/sshd_config
sudo ls -la /etc/ssh/sshd_config.d || true
sudo grep -RniE '(AllowUsers|DenyUsers|Match|MaxStartups|PasswordAuthentication|PubkeyAuthentication)' /etc/ssh/sshd_config.d || true

# 三、检查 fail2ban
sudo systemctl status fail2ban --no-pager || true
sudo fail2ban-client status || true
sudo fail2ban-client status sshd || true
sudo journalctl -u fail2ban -n 100 --no-pager || true

# 四、检查防火墙
sudo ufw status verbose || true
sudo iptables -S | head -100 || true

# 五、检查 hosts.deny
sudo cat /etc/hosts.deny || true
sudo cat /etc/hosts.allow || true

# 六、检查资源
df -h
free -h
uptime

# 七、检查认证日志
sudo tail -200 /var/log/auth.log || true
sudo tail -200 /var/log/secure || true
```

### 10.2 优先级 2：根据诊断结果修复

#### 如果是 fail2ban 封禁

```bash
# 查看被封 IP
sudo fail2ban-client status sshd

# 解封特定 IP（替换为实际 IP）
sudo fail2ban-client set sshd unbanip <YOUR_IP>

# 不要永久关闭 fail2ban
```

#### 如果是 sshd_config 配置问题

```bash
# 备份配置
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%Y%m%d_%H%M%S)

# 编辑配置（移除或修改 AllowUsers/DenyUsers/Match 等）
sudo nano /etc/ssh/sshd_config

# 测试配置
sudo sshd -t

# 重启服务
sudo systemctl restart sshd
```

#### 如果是 MaxStartups 问题

```bash
# 编辑配置
sudo nano /etc/ssh/sshd_config
# 添加或修改：MaxStartups 30:30:100

# 测试并重启
sudo sshd -t
sudo systemctl restart sshd
```

#### 如果是资源问题

```bash
# 清理磁盘
sudo du -h /var/log | sort -rh | head -20
sudo journalctl --vacuum-time=7d

# 检查内存
free -h
sudo systemctl restart sshd
```
