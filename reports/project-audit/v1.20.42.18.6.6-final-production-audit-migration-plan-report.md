## 02. PM2 Restart Root Cause Analysis

### Finding: 190 restarts are from DEPLOYMENTS, not crashes

**Evidence:**
1. PM2 process created: 2026-06-20 (3 days ago)
2. 190 restarts / 3 days = ~63 restarts/day
3. Current memory: 311MB (well under 1G limit) — NOT OOM
4. `unstable_restarts: 0` — no recent instability
5. Error log: only 15 lines total, 3 unique error types (all Next.js framework bugs, not crashes)
6. No dmesg OOM kills, no journalctl restart entries
7. Out log shows repeated "next start" — consistent with `pm2 restart` commands

**Root cause:** Each deployment runs `pm2 restart xixiong-saas --update-env`. With v18.6.5 through v18.6.5.5 (6+ deploys in 2 days), plus earlier iterations, the 190 count is cumulative since PM2 was first started.

**Error log breakdown (15 lines total):**
- 4× "client reference manifest for /bbs/[slug]" — Next.js framework bug
- 2× "Failed to load /500.html" — missing 500 page
- 1× "Failed to find Server Action" — stale deployment artifact

**Verdict:** NOT a stability risk. NOT blocking migration. The restart count will reset on new server (`pm2 reset`).

**Recommendations:**
- Run `pm2 reset xixiong-saas` after stable deployment to reset counter
- Add `pages/500.html` or custom error page to fix 500 error
- The /bbs/[slug] client reference manifest bug is a known Next.js issue

## 10. Release Governance

### 分支策略
| 分支 | 用途 |
|------|------|
| main | 稳定生产分支 |
| staging | 预发布分支 |
| feature/* | 功能分支 |
| hotfix/* | 紧急修复 |

### 发布流程
1. 需求确认 + 任务编号
2. feature/* 分支开发
3. 单元测试 (vitest)
4. 本地 build 验证
5. migration 检查 (prisma migrate status)
6. 合并到 staging
7. staging 部署 + smoke test
8. 生产备份 (backup-prod.sh)
9. 合并到 main + 生产部署 (deploy-safe.sh)
10. 生产 smoke test (smoke-test.sh)
11. 观察窗口 (1-2h)
12. 发布报告
13. 回滚准备

### 规则
- 所有变更先到 staging
- 生产部署必须用 deploy-safe.sh
- 生产部署前必须备份 DB
- 有 migration 必须单独标记
- **禁止 prisma db push**
- 禁止直接改生产代码
- 禁止无报告上线
- 禁止未 smoke test 就说通过
- PM2 restart count 必须记录
- deploy-version.json 必须更新
- 每次上线有 changelog + rollback note
