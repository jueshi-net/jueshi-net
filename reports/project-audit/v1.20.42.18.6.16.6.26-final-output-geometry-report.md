## 二、纸张几何根因分析

### v6.25 的 iframe 尺寸问题

```typescript
// v6.25（错误）
iframe.style.width = "1px";
iframe.style.height = "1px";
iframe.style.overflow = "hidden";
```

**根因：** 1px × 1px 的 iframe 导致浏览器无法正确渲染页面内容。浏览器在极小尺寸的 iframe 中会裁切内容，即使 CSS `@page` 设置了正确的纸张尺寸。

### v6.26 修复

```typescript
// v6.26（正确）
const paperWidthPx = Math.ceil(paperWidthMm * 3.7795275591); // mm to px at 96 DPI
const paperHeightPx = Math.ceil(paperHeightMm * 3.7795275591);
iframe.style.left = "-9999px";  // 移出可视区域
iframe.style.top = "-9999px";
iframe.style.width = `${paperWidthPx + 20}px`;  // 实际纸张宽度 + 边距
iframe.style.height = `${paperHeightPx * pages.length + 20}px`;  // 所有页面高度
iframe.style.overflow = "visible";  // 允许内容溢出
```

**修复原理：**
- iframe 尺寸 = 实际纸张像素尺寸（mm × 3.7795275591 = px at 96 DPI）
- 多页模式：高度 = 单页高度 × 页数
- 位置：`left: -9999px` 移出可视区域，用户看不到
- `overflow: visible` 确保内容不被裁切

## 四、PNG 尺寸修复说明

PNG 导出使用 `html-to-image` 的 `toPng()`，直接渲染 `paperRef.current`（单个纸张元素），不受 iframe 尺寸影响。PNG 导出应该已经正确。

**但需要用户验证：** packageCount=15 时是否导出 15 张 PNG。

## 五、多页 PNG 修复说明

当前 PNG 导出逻辑（`handleExportPng`）只导出第一页（`paperRef.current`）。如果用户需要导出所有 15 页，需要额外的多页 PNG 导出功能。

**本轮范围：** 只修复打印裁切问题。多页 PNG 导出作为后续任务。
