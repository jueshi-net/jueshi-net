## P0/P1/P2 定义

### P0 - 立即修复（影响核心功能或安全）

- 登录/登出失败
- 数据丢失
- 权限绕过
- 生产环境崩溃
- 9833416@qq.com 被修改
- role 被会员覆盖

**处理流程：**
1. 立即停止用户测试
2. 最小改动修复
3. 测试验证
4. 紧急部署
5. 写 hotfix 报告
6. 通知用户继续测试

### P1 - Beta 前建议修复（影响用户体验）

- UI 细节问题
- 文案误导
- 功能不完整
- 移动端适配
- 文档缺失

**处理流程：**
1. 记录问题
2. 准备修复代码
3. 测试验证
4. 等待用户测试结束
5. 统一发版部署

### P2 - Beta 后必须做（功能完善）

- 新奖励权益实现
- 权限审计日志
- 内容中心后台化
- CI 自动测试
- Schema 拆分

**处理流程：**
1. 记录需求
2. 设计文档
3. 等待 Beta 结束
4. 排期开发

## P0 Hotfix 流程

1. **确认问题**
   - 用户报告 bug
   - 验证是否 P0
   - 评估影响范围

2. **最小修复**
   - 只改必要代码
   - 不引入新功能
   - 不修改无关模块

3. **测试验证**
   - 本地测试通过
   - 相关回归测试通过
   - 不影响其他功能

4. **紧急部署**
   - Build 新版本
   - 更新 deploy-version.json
   - PM2 restart
   - 验证生产

5. **写 Hotfix 报告**
   - 说明 P0 原因
   - 记录改动内容
   - 列出测试证据
   - 通知用户继续测试
