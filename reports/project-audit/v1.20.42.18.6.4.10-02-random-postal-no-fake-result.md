# v1.20.42.18.6.4.10-02 — Random Postal Code No Fake Results

## Root Cause

The advanced API (`/api/postal-codes/advanced/route.ts`) used `normalized.startsWith(city.postalPrefix)` without validating the postal code format. This meant any code starting with a city prefix (e.g. "M99999" matching Toronto's "M" prefix) returned a result, even though the code doesn't exist.

## Fix

### Advanced API (`handleRegionSearch`)
- Added format validation: `const formatValid = countryData ? new RegExp(countryData.formatRegex).test(normalized) : false;`
- Only perform prefix matching when `formatValid === true`
- Added `note` field: "邮编格式正确，区域信息基于邮编前缀推断，具体地址请以数据库查询或官方入口为准。"

### Main API (`/api/postal-codes/route.ts`)
- Postal code search uses exact + prefix match on `normalizedPostalCode`
- "ZZZ999" normalized to "ZZZ999" — no postal code starts with "ZZZ999" → returns 0 results
- "10000" normalized to "10000" — matches "1000000" (JP Tokyo) via prefix → returns 11 results
