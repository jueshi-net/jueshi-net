### 3.4 DNS 修复清单

**必须修复**:

#### 1. SPF 记录（必须）

**当前**: `v=spf1 -all`（拒绝所有）

**修改为**（使用赛博活佛邮局）:
```
v=spf1 include:cybermonk.com ~all
```

或（使用固定 IP）:
```
v=spf1 ip4:192.129.155.149 ~all
```

或（使用第三方服务，以 Resend 为例）:
```
v=spf1 include:_spf.resend.com ~all
```

**修改位置**: 域名注册商 DNS 管理面板

**记录类型**: TXT  
**主机**: @  
**值**: 上述 SPF 字符串  
**TTL**: 3600

#### 2. DKIM 记录（推荐）

**当前**: `v=DKIM1; p=`（公钥为空）

**修复步骤**:
1. 在邮件服务器生成 DKIM 密钥对
2. 获取公钥
3. 更新 DNS TXT 记录

**示例**（以 Resend 为例）:
```
类型: TXT
主机: resend._domainkey
值: v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQ...
TTL: 3600
```

#### 3. DMARC 记录（可选优化）

**当前**: `v=DMARC1; p=reject; sp=reject; adkim=s; aspf=s;`

**建议修改为**（宽松模式，便于调试）:
```
v=DMARC1; p=quarantine; sp=quarantine; adkim=r; aspf=r; rua=mailto:dmarc@jueshi.net
```

**说明**:
- `p=quarantine`: 失败邮件放入垃圾箱（而非拒绝）
- `adkim=r; aspf=r`: 宽松对齐
- `rua=mailto:dmarc@jueshi.net`: 接收聚合报告

### 4.2 上次 403 根因分析

**事件回顾**: v1.20.42.7.08 尝试配置 Cloudflare IP 白名单，导致正常访问返回 403

**根因分析**:

1. **IPv6 地址未完整加入白名单**
   - Cloudflare IPv6 段: 6 个
   - 实际访问使用的 IPv6 地址可能不在列表中
   - 日志显示: `client: 2605:52c0:2:2309:fc01:70ff:fec6:4505`（DMIT Cloud Services，非 Cloudflare）

2. **Nginx 缺少 real_ip 配置**
   - 当前 Nginx 没有配置 `set_real_ip_from`
   - Nginx 看到的客户端 IP 是 Cloudflare 的 IP，而不是真实用户 IP
   - 这导致 IP 白名单判断错误

3. **Cloudflare IP 段可能不完整**
   - IPv4: 14 个段
   - IPv6: 6 个段
   - Cloudflare 可能使用未公开的 IP 段

**结论**: 403 是由于 IP 白名单配置不完整 + 缺少 real_ip 配置导致
