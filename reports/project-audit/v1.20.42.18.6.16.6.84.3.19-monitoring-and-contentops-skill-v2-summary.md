## PART A — 服务器监控探针

### 为什么后续没有持续发送

**根因分析**:

1. **PM2 进程重启后未恢复**: 监控脚本作为 cron job 运行，PM2 重启后 cron 未自动恢复
2. **缺乏持久化机制**: 监控脚本未注册为 PM2 进程，无法自动重启
3. **缺乏告警恢复机制**: 监控停止后无自动恢复逻辑

**时间线**:

- 2026-07-03: 监控探针部署成功，开始发送数据
- 2026-07-03: PM2 重启 (xixiong-saas restart)
- 2026-07-03: 监控 cron job 未恢复
- 2026-07-04: 发现监控停止

### 监控 Agent 是否需要重建

**结论**: ✅ 需要重建

**原因**:

1. 当前监控脚本是临时 cron job，非持久化进程
2. 缺乏自动恢复机制
3. 缺乏告警恢复逻辑
4. 需要独立 PM2 进程确保稳定运行

## PART B — ContentOps v2 升级方案

### ContentOps 当前为什么简陋

#### 原因 1: 缺乏内容质量门槛

**现状**: Bot 生成内容后直接创建 draft，不检查质量。

**问题**:
- Checklist 可能只有 2-3 个 group，10 个 item
- Guide 可能只有 500 字，3 个 section
- Topic 可能只有 100 字 intro，2 个子主题
- FAQ 可能只有 2-3 个
- 缺乏 pitfalls、internalLinks、related tools

#### 原因 2: 不支持长文本/文件输入

**现状**: Bot 只支持简单文本输入，无法处理：
- 用户粘贴的长文章
- 用户上传的 PDF/Word 文件
- 竞品页面内容
- 参考资料

**问题**: Bot 只能基于简单提示生成内容，缺乏深度。

#### 原因 3: 缺乏 SEO/GEO 增强规则

**现状**: SEO/GEO 字段可选，不强制。

**问题**:
- metaTitle/metaDescription 可能缺失
- keywords 可能不完整
- structuredData 可能缺失
- FAQ schema 可能缺失

#### 原因 4: 缺乏"洗稿/改写"安全规则

**现状**: Bot 可能直接复制竞品内容。

**问题**:
- 版权风险
- 内容同质化
- 缺乏独特价值

#### 原因 5: Telegram 交互过于简单

**现状**: 用户只能发送简单文本，Bot 直接生成。

**问题**:
- 无法预览大纲
- 无法调整质量
- 无法指定目标用户
- 无法指定国家/地区

### ContentOps v2 应支持的输入模式

#### 模式 1: 简单文本输入

```
帮我创建一个新加坡留学清单
```

Bot 基于提示生成完整内容。

#### 模式 2: 长文本粘贴

```
参考这段资料，帮我洗成我们自己的留学清单：
[粘贴 2000 字文章]
```

Bot 提取关键信息，重新组织语言，生成原创内容。

#### 模式 3: 文件上传

```
[上传 PDF/Word 文件]
参考这个文件，帮我生成指南
```

Bot 解析文件内容，提取关键信息，生成原创内容。

#### 模式 4: 竞品 URL

```
参考这个页面，帮我生成我们自己的清单：
https://competitor.com/singapore-student-checklist
```

Bot 抓取页面内容，提取关键信息，生成原创内容。

#### 模式 5: 混合输入

```
参考这段资料和这个文件，帮我生成指南：
[粘贴文本]
[上传文件]
```

Bot 综合多个来源，生成完整内容。

### 文件/长文本/竞品资料处理方案

#### 长文本处理流程

```
1. 用户粘贴长文本 (500-5000 字)
2. Bot 识别内容类型 (checklist/guide/topic)
3. Bot 提取关键信息：
   - 标题
   - 目标用户
   - 国家/地区
   - 搜索意图
   - 关键步骤/要点
   - FAQ
   - 注意事项
4. Bot 生成大纲
5. 用户确认大纲
6. Bot 基于大纲生成完整内容
7. Bot 检查质量门槛
8. 用户确认创建 draft
```

#### 文件处理流程

```
1. 用户上传文件 (PDF/Word/TXT)
2. Bot 解析文件内容
3. Bot 提取关键信息 (同长文本处理)
4. Bot 生成大纲
5. 用户确认大纲
6. Bot 基于大纲生成完整内容
7. Bot 检查质量门槛
8. 用户确认创建 draft
```

#### 竞品 URL 处理流程

```
1. 用户发送竞品 URL
2. Bot 抓取页面内容
3. Bot 提取关键信息 (同长文本处理)
4. Bot 应用"洗稿/改写"安全规则
5. Bot 生成大纲
6. 用户确认大纲
7. Bot 基于大纲生成完整内容
8. Bot 检查质量门槛
9. 用户确认创建 draft
```
