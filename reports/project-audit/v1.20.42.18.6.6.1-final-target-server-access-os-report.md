## 2. 操作系统选择

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| A: 重装 Ubuntu 24.04 LTS | 与生产完全一致，零适配风险 | 需 15-30 分钟重装 | ⭐⭐⭐⭐⭐ |
| B: 保留 Debian 13 | 不用重装 | PG 版本差异(17 vs 16)，脚本适配风险 | ⭐⭐ |

**推荐选择: 重装 Ubuntu 24.04 LTS**

理由：当前生产所有脚本（deploy-safe.sh, health-check.sh, backup-db.sh, Nginx config, PM2 ecosystem, cron jobs）均基于 Ubuntu 24.04 验证。迁移本身已有足够风险，不应叠加 OS 差异。如果新服务器尚未放数据，重装成本远低于排错成本。

**Debian 13 是否可用:** 技术上可用，但需跑完整 bootstrap preflight，且 PostgreSQL 版本差异是最大风险。

## 3. deploy 用户初始化方案

### 步骤概要
1. root 登录新服务器
2. `adduser deploy` + `usermod -aG sudo deploy`
3. 创建 ~/.ssh，写入 public key，权限 700/600
4. `echo "deploy ALL=(ALL) NOPASSWD: ALL" > /etc/sudoers.d/deploy`
5. 新 SSH session 验证 `ssh -i ~/.ssh/jueshi-prod-v2 deploy@NEW_SERVER_IP`
6. 验证 `sudo -v`
7. 确认后才可禁用密码登录

**保留 emergency access:** 服务商 console / root 密码保留，避免锁死。

详细步骤见: `v1.20.42.18.6.6.1-03-target-deploy-user-plan.md`

## 4. SSH 安全加固方案

### sshd_config 推荐
- PasswordAuthentication no（key 验证后）
- PubkeyAuthentication yes
- PermitRootLogin prohibit-password
- AllowUsers deploy
- Fail2ban sshd jail 启用
- UFW: 22/80/443

### 当前生产参考
- PermitRootLogin: no ✅
- PasswordAuthentication: yes ⚠️（新服务器应更严格）
- Fail2ban: 激活，已封 655 IP ✅
- UFW: 激活 ✅
- sudo: deploy NOPASSWD: ALL ✅

### 安全原则
- key 登录验证前不禁用密码
- sudo 验证前不关闭 root
- 保留 console emergency access

详细配置见: `v1.20.42.18.6.6.1-04-ssh-hardening-plan.md`
