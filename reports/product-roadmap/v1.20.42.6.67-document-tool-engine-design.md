## 一、设计目标

### 1.1 核心目标

设计一个统一的 **Document Tool Engine**，用于快速实现多个外贸文档工具。

### 1.2 设计原则

1. **统一数据模型**: 所有文档工具共享基础字段结构
2. **组件复用**: CompanyProfile、Buyer/Consignee/Shipper 等可复用
3. **保存/恢复统一**: 使用 ToolDocumentDraft / ToolDocumentHistory
4. **Workspace 集成**: 所有文档工具自动出现在 Workspace
5. **EventLog 规范**: 统一的创建/更新/恢复事件记录
6. **扩展性**: 新增文档工具只需定义 schema，不需要重写逻辑

### 1.3 非目标

- ❌ 本轮不开发
- ❌ 不改 Prisma schema
- ❌ 不新增 migration
- ❌ 不实现 PDF/打印
- ❌ 不实现模板渲染

### 4.2 核心组件

#### 4.2.1 Document Schema Definition

每个文档工具定义一个 schema，包含：

```typescript
interface DocumentSchema {
  // 基础信息
  toolKey: string;           // 工具标识，如 'packing-list'
  toolName: string;          // 工具名称，如 'Packing List'
  version: string;           // schema 版本
  
  // 参与方
  parties: PartySchema[];    // 卖方、买方、收货人等
  
  // 商品明细
  items: ItemsSchema;        // 商品列表结构
  
  // 金额与条款
  totals?: TotalsSchema;     // 总计、货币、贸易条款
  
  // 附加字段
  additionalFields?: FieldSchema[];  // 文档特有字段
  
  // 校验规则
  validation?: ValidationSchema;
}
```

#### 4.2.2 Reusable Components

| 组件 | 用途 | 复用场景 |
|---|---|---|
| PartyInfo | 卖方/买方/收货人信息 | 所有文档 |
| ItemsTable | 商品明细表格 | 所有文档 |
| AmountSection | 金额、货币、贸易条款 | 发票类文档 |
| PackageInfo | 包装信息（件数、重量、体积） | 装箱单类文档 |
| ShippingInfo | 运输信息（起运港、目的港） | 物流类文档 |

#### 4.2.3 Save/Restore Service

统一的保存/恢复接口：

```typescript
interface DocumentService {
  // 保存草稿
  saveDraft(toolKey: string, data: any): Promise<Draft>;
  
  // 恢复草稿
  restoreDraft(draftId: string): Promise<any>;
  
  // 保存历史版本
  saveHistory(draftId: string, version: number): Promise<History>;
  
  // 获取历史列表
  getHistoryList(toolKey: string): Promise<History[]>;
}
```

## 六、API 草案

### 6.1 保存草稿

```
POST /api/tools/documents/:toolKey/draft
Body: { data: DocumentData }
Response: { draftId, updatedAt }
```

### 6.2 恢复草稿

```
GET /api/tools/documents/:toolKey/draft/:draftId
Response: { data: DocumentData, version }
```

### 6.3 保存历史版本

```
POST /api/tools/documents/:toolKey/draft/:draftId/history
Body: { version, data: DocumentData }
Response: { historyId, createdAt }
```

### 6.4 获取历史列表

```
GET /api/tools/documents/:toolKey/history
Response: { histories: History[] }
```

## 八、保存/恢复流程

### 8.1 保存流程

```
用户点击"保存草稿"
  ↓
前端收集表单数据
  ↓
调用 POST /api/tools/documents/:toolKey/draft
  ↓
后端保存到 ToolDocumentDraft
  ↓
记录 EventLog (document_draft_saved)
  ↓
返回 draftId
  ↓
前端显示"保存成功"
```

### 8.2 恢复流程

```
用户点击"恢复草稿"
  ↓
前端显示历史版本列表
  ↓
用户选择版本
  ↓
调用 GET /api/tools/documents/:toolKey/draft/:draftId
  ↓
后端从 ToolDocumentDraft 读取
  ↓
返回文档数据
  ↓
前端填充表单
  ↓
用户确认恢复
```

## 十二、风险

### 12.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| Schema 设计不够灵活 | 后续文档工具需要大改 | 先实现 2-3 个工具验证 |

| 风险 | 影响 | 缓解措施 |

| 用户需求不明确 | 做出来的工具不符合需求 | 先收集用户反馈 |
