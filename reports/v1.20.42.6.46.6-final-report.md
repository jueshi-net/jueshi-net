## 完成的工作

### 1. 修复 remark/remarks 字段不一致问题 ✅

**问题根因**:
- Template 定义使用 `remark`（单数）
- 旧数据可能使用 `remarks`（复数）
- 恢复时只读取 `remark`，导致旧数据的 `remarks` 字段丢失

**修复方案**:
在 `src/app/(public)/tools/documents/[type]/page.tsx` 的恢复逻辑中添加 fallback：
```typescript
// Normalize remark/remarks field for backward compatibility
const normalizedLineItems = docData.lineItems.map((item: any) => ({
  ...item,
  remark: item.remark ?? item.remarks ?? '',
}));
setLineItems(normalizedLineItems);
```

**兼容性**:
- ✅ 新数据使用 `remark` 字段
- ✅ 旧数据使用 `remarks` 字段时自动 fallback
- ✅ 两个字段都不存在时默认为空字符串

### 2. 添加 EventLog 写入 ✅

**问题根因**:
- `/api/user/documents` API 保存文档时没有写入 EventLog
- 导致 Document_Save 事件数据缺失

**修复方案**:
在 `src/app/api/user/documents/route.ts` 的 POST 方法中添加 EventLog 写入：
```typescript
// Fire Document_Save EventLog
try {
  await prisma.eventLog.create({
    data: {
      eventType: "Document_Save",
      action: "Document_Save",
      path: `/tools/documents/${documentType}`,
      toolName: documentType,
    },
  });
} catch (eventErr: any) {
  // EventLog write failure should not block document save
  console.error("[POST /api/user/documents] EventLog write failed:", eventErr.message);
}
```

**特性**:
- ✅ EventLog 写入失败不会阻塞文档保存
- ✅ 记录 documentType、path、toolName
- ✅ 错误日志记录到 PM2 error log

### 3. 修复数据库连接配置 ✅

**问题根因**:
- `.env.production` 中的 DATABASE_URL 端口配置为 5555
- PostgreSQL 实际监听在 5432 端口

1. 修改端口：`5555` → `5432`
2. URL 编码密码：`***@Secure` → `***%40Secure`
3. 更新 PM2 dump.pm2 缓存的环境变量
4. 重启 PM2 进程
