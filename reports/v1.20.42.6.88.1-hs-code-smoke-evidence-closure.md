## 六、部署流程小结

### 6.1 为什么 v6.88 部署没有直接使用稳定的 npm ci 流程

**问题描述**:
- `deploy-production.sh` 脚本中使用 `npm ci` 命令
- `npm ci` 在生产环境（`NODE_ENV=production`）下会跳过 `devDependencies`
- `@tailwindcss/postcss` 是 `devDependency`，导致构建失败

**根本原因**:
```json
{
  "devDependencies": {
    "@tailwindcss/postcss": "^4.3.1",
    "tailwindcss": "^4"
  }
}
```

`npm ci --production` 或 `NODE_ENV=production npm ci` 会跳过 devDependencies，但 Next.js 构建需要这些依赖。

### 6.2 @tailwindcss/postcss 是否已存在于 package.json 和 package-lock.json

**验证结果**: ✅ 已存在

**package.json**:
```json
{
  "devDependencies": {
    "@playwright/test": "^1.59.1",
    "@tailwindcss/postcss": "^4.3.1",
    "tailwindcss": "^4"
  }
}
```

**package-lock.json**:
```json
{
  "devDependencies": {
    "@tailwindcss/postcss": {
      "version": "4.3.1"
    }
  }
}
```

### 6.3 deploy-production.sh 后续是否能在干净环境下完成 build

**当前状态**: ❌ 不能

**问题**:
- `deploy-production.sh` 使用 `npm ci`，会跳过 devDependencies
- 需要手动执行 `npm install --ignore-scripts` 安装所有依赖
- 然后手动执行 `npx prisma generate` 和 `npm run build`

**临时解决方案**（v6.88 部署使用）:
```bash
# 1. 使用 --ignore-scripts 安装所有依赖（包括 devDependencies）
npm install --ignore-scripts

# 2. 手动执行 postinstall 脚本
export NODE_ENV=production
source .env.production
npx prisma generate
npm run build
```

### 6.4 是否是临时方案

**答案**: ✅ 是临时方案

**原因**:
1. `deploy-production.sh` 脚本需要修改，以正确处理 devDependencies
2. 有两种修复方案：
   - **方案 A**: 修改 `deploy-production.sh`，使用 `npm ci --include=dev` 或 `npm install`
   - **方案 B**: 将 `@tailwindcss/postcss` 和 `tailwindcss` 移到 `dependencies`（不推荐）

**建议**:
- 修改 `deploy-production.sh`，使用 `npm ci --include=dev` 或 `npm install`
- 或者在构建前显式安装 devDependencies

**示例修复**:
```bash
# 修改 deploy-production.sh
echo "Installing dependencies (including dev for build)..."
npm ci --include=dev  # 或 npm install
```
