## 一、当前问题

### 1.1 当前部署方式

| 项目 | 现状 |
|---|---|
| 部署方式 | rsync 直接覆盖生产目录 |
| 环境数量 | 仅生产环境 |
| 回滚方式 | 手动 rsync 旧版本 |

| 测试环境 | 无 |

### 1.2 风险

1. **直接改生产**: 任何代码变更直接影响真实用户
2. **无回滚保障**: 出问题后需要手动恢复
3. **无测试验证**: 无法在生产前验证变更
4. **无灰度发布**: 无法逐步放量
5. **无分支管理**: 所有变更直接进 main

### 4.3 Symlink 发布流程

```bash
#!/bin/bash
# deploy-production.sh

set -e

VERSION="v1.20.42.6.67"
TIMESTAMP=$(date +%Y%m%d-%H%M%S)
RELEASE_DIR="/home/deploy/releases/${VERSION}-${TIMESTAMP}"

echo "=== Deploying to Production ==="

# 1. 创建新 release 目录
mkdir -p $RELEASE_DIR
cd $RELEASE_DIR

# 2. 拉取代码
git clone --branch main --depth 1 git@github.com:nnrwsm-cloud/jueshibbx.git .

# 3. 安装依赖
pnpm install --frozen-lockfile --prod

# 4. 生成 Prisma Client
pnpm prisma generate

# 5. 构建
pnpm build

# 6. 复制共享文件
cp /home/deploy/shared/.env.production .
ln -s /home/deploy/shared/uploads ./uploads

# 7. 健康检查（新 release）
NODE_ENV=production node -e "require('./.next/required-server-files.json')" || exit 1

# 8. 切换 symlink
ln -sfn $RELEASE_DIR /home/deploy/current

# 9. 重启 PM2
pm2 reload xixiong-saas --update-env

# 10. 验证
sleep 5
curl -f https://jueshi.net/health || {
  echo "Health check failed, rolling back..."
  # 回滚到上一个版本
  PREV_RELEASE=$(ls -t /home/deploy/releases/ | head -2 | tail -1)
  ln -sfn /home/deploy/releases/$PREV_RELEASE /home/deploy/current
  pm2 reload xixiong-saas --update-env
  exit 1
}

# 11. 清理旧 release（保留最近 5 个）
ls -t /home/deploy/releases/ | tail -n +6 | xargs -I {} rm -rf /home/deploy/releases/{}

echo "=== Production Deploy Complete ==="
```

## 五、Git 分支策略

### 5.1 分支模型

```
main (production)
│
├── develop (staging)
│   │
│   ├── feature/packing-list
│   ├── feature/proforma-invoice
│   └── fix/login-bug
│
├── release/v1.20.42.6.68
│   └── (from develop, merge to main)
│
└── hotfix/critical-bug
    └── (from main, merge to main and develop)
```

### 5.2 分支说明

| 分支 | 用途 | 部署目标 |
|---|---|---|
| `main` | 生产代码 | Production |
| `develop` | 开发集成 | Staging |
| `feature/*` | 新功能开发 | 无 |
| `release/*` | 发布准备 | Staging → Production |
| `hotfix/*` | 紧急修复 | Production |

### 5.3 分支流程

#### 新功能开发

```
1. 从 develop 创建 feature 分支
   git checkout develop
   git checkout -b feature/packing-list

2. 开发完成后提交 PR 到 develop
   git push origin feature/packing-list
   # GitHub PR: feature/packing-list → develop

3. Code Review 后合并到 develop
   # 自动部署到 staging

4. Staging 验证通过后，创建 release 分支
   git checkout develop
   git checkout -b release/v1.20.42.6.68

5. Release 分支合并到 main
   # PR: release/v1.20.42.6.68 → main
   # 打 tag: v1.20.42.6.68
   # 部署到 production

6. Release 分支合并回 develop
   # 保持 develop 同步
```

#### 紧急修复

```
1. 从 main 创建 hotfix 分支
   git checkout main
   git checkout -b hotfix/critical-bug

2. 修复完成后提交 PR 到 main
   # GitHub PR: hotfix/critical-bug → main

3. 合并到 main 并打 tag
   # 自动部署到 production

4. Hotfix 分支合并回 develop
   # 保持 develop 同步
```

## 七、回滚步骤

### 7.1 快速回滚（Symlink 切换）

```bash
#!/bin/bash
# rollback.sh

echo "=== Rolling Back Production ==="

# 1. 找到上一个 release
PREV_RELEASE=$(ls -t /home/deploy/releases/ | head -2 | tail -1)

if [ -z "$PREV_RELEASE" ]; then
  echo "No previous release found!"
  exit 1
fi

echo "Rolling back to: $PREV_RELEASE"

# 2. 切换 symlink
ln -sfn /home/deploy/releases/$PREV_RELEASE /home/deploy/current

# 3. 重启 PM2
pm2 reload xixiong-saas --update-env

# 4. 验证
sleep 5
curl -f https://jueshi.net/health || {
  echo "Rollback verification failed!"
  exit 1
}

echo "=== Rollback Complete ==="
```

### 7.2 数据库回滚

**原则**: 数据库回滚风险极高，尽量避免。

**方案**:

1. **向前兼容**: Migration 只增加字段，不删除/修改
2. **备份**: 每次 migration 前备份
3. **手动恢复**: 如必须回滚，从备份恢复

```bash
# 数据库备份
pg_dump "$DATABASE_URL" > /home/deploy/shared/backups/db-$(date +%Y%m%d-%H%M%S).dump

# 数据库恢复（危险操作）
psql "$DATABASE_URL" < /home/deploy/shared/backups/db-XXXXXXXX-XXXXXX.dump
```

## 八、Migration 安全流程

### 8.1 Migration 前

```
1. 备份生产数据库
   pg_dump "$DATABASE_URL" > backup.dump

2. 在 staging 测试 migration
   pnpm prisma migrate deploy --schema=staging

3. 验证 staging 功能正常
   - 所有页面可访问
   - 核心功能可用
   - 无报错
```

### 8.2 Migration 中

```
1. 停止生产 PM2（可选，取决于 migration 类型）
   pm2 stop xixiong-saas

2. 执行 production migration
   pnpm prisma migrate deploy

3. 启动 PM2
   pm2 start xixiong-saas
```

### 8.3 Migration 后

```
1. Runtime Guard 验证
   node scripts/verify-runtime-db-env.mjs

2. 功能验证
   - 登录正常
   - 核心工具可用
   - 保存/恢复正常

3. 监控 30 分钟
   - PM2 logs 无错误
   - 用户反馈正常
```

## 九、Feature Flag 方案

### 9.1 Feature Flag 结构

```typescript
interface FeatureFlags {
  // 新功能
  packingList: boolean;
  proformaInvoice: boolean;
  
  // Beta 功能
  betaForum: boolean;
  betaWorkspace: boolean;
  
  // 实验功能
  newCheckout: boolean;
}
```

### 9.2 Feature Flag 策略

| 阶段 | 策略 | 说明 |
|---|---|---|
| 开发中 | `false` | 所有人不可见 |
| 内部测试 | 内部账号 `true` | 仅内部账号可见 |
| Beta 测试 | Beta 用户 `true` | Beta 用户可见 |
| 全量发布 | `true` | 所有人可见 |

### 9.3 Feature Flag 实现

```typescript
// lib/feature-flags.ts

export function getFeatureFlag(flag: string, user?: User): boolean {
  // 1. 检查环境变量（全局开关）
  if (process.env[`FEATURE_${flag.toUpperCase()}`] === 'true') {
    return true;
  }
  
  // 2. 检查用户角色
  if (user?.role === 'admin') {
    return true;  // 管理员始终可见
  }
  
  // 3. 检查 Beta 标记
  if (user?.isBetaUser && isBetaFeature(flag)) {
    return true;
  }
  
  // 4. 默认关闭
  return false;
}
```
