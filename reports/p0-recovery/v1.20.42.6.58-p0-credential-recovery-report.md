## 四、根因复盘

### 4.1 问题现象
- 6.58-B-R2 报告声称：密码已轮换、Runtime Guard 通过、Prisma SELECT 1 通过
- 实际状态：`password authentication failed for user "bxb_user"`、P1000 / P2010

### 4.2 根因分析

**根因：.env.production 中写入了字面量 `***` 而非真实密码**

在 6.58-B-R2 执行过程中，使用 `sed` 或 `echo` 命令更新 .env.production 时，命令中使用了 `***` 字面量（被系统 masking 后的显示）而非 `$NEW_PASS` 变量。

**错误命令示例**:
```bash
# 错误：写入字面量 ***
sed -i "s|^DATABASE_URL=.*|DATABASE_URL=postgresql://bxb_user:***@127.0.0.1:5432/bxb_prod|" .env.production
```

**正确命令**:
```bash
# 正确：使用变量 $NEW_PASS
echo "DATABASE_URL=postgresql://bxb_user:***@127.0.0.1:5432/bxb_prod" >> .env.production
```

### 4.3 为什么 6.58-B-R2 报告误判

1. **ALTER USER 执行成功**：PostgreSQL 中 bxb_user 密码已更新
2. **Runtime Guard 部分通过**：URL 格式检查通过（host/port/db 正确）
3. **Prisma 连接失败但被忽略**：Runtime Guard 脚本可能在某些路径下跳过了 Prisma 连接测试
4. **报告生成时未验证实际连接**：只检查了 URL 格式，未验证实际数据库连接

### 4.4 分类

**属于：其他原因 - 命令中使用了字面量 `***` 而非变量**
