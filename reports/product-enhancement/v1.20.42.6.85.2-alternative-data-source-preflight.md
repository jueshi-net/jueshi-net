## 4. Hong Kong (HK) — Special Case: Does NOT Use Postal Codes 🎯

### Critical Finding
**Hong Kong does NOT use postal codes for domestic mail.**

From Wikipedia and multiple sources:
- Hongkong Post deems postal code system unnecessary
- Advises leaving postcode field blank
- Alternative fillers: "000", "0000", "000000", or "HKG"
- Only used for mail from mainland China

### Current Status
- DB has 1 record: `999077` (Hong Kong Special Administrative Region)
- This is a placeholder, not a real postal code system
- GeoNames also only has 1 record

### Recommendation
**Do NOT import more data. Change UI messaging instead.**

**Suggested UI changes**:
1. Change HK coverage status from "🔴 极少数据" to "ℹ️ 特殊地区"
2. Add explanation: "香港通常不使用邮政编码。填写地址时，邮编栏位可留空或填写 'HKG'。"
3. Remove "数据极少" warning, replace with informational message
4. Keep the 1 record for reference but don't treat as data gap

### Implementation
**No database import needed.**  
**Frontend-only change**: Update coverage status config and UI messaging for HK.

## 5. OpenStreetMap (OSM) Assessment ⚠️

### OSM as Data Source
- **URL**: https://www.openstreetmap.org/
- **License**: Open Database License (ODbL)
- **Commercial use**: ✅ Allowed with attribution
- **Redistribution**: ✅ Allowed with attribution + share-alike
- **Data quality**: Variable — community-maintained
- **Postal code coverage**: Incomplete for many countries
- **Format**: OSM XML/PBF, needs extraction

### OSM Limitations
1. **Not a postal code database** — OSM is a map, not a postal code registry
2. **Postal code data is sparse** — many countries have incomplete coverage
3. **Extraction is complex** — needs Overpass API or Geofabrik extracts
4. **Quality varies** — community-maintained, no official verification
5. **Nominatim is NOT for bulk queries** — usage policy restricts heavy use

### OSM Recommendation
**Do NOT use OSM as primary postal code source.**

**Acceptable uses**:
- Supplementary geocoding (lat/lon for known postal codes)
- Fallback for missing coordinates
- Verification of existing data

**Not acceptable**:
- Primary postal code database
- Production bulk queries via Nominatim
- Replacing official postal data
