## 一、当前系统审计摘要

### 1.1 Prisma Schema 关键模型

| 模型 | 用途 | 与任务链关系 |
|---|---|---|
| ToolDocumentDraft | 工具草稿（25+ 类型） | 可关联但不推荐复用 |

### 1.2 现有草稿系统

- **ToolDocumentDraft**：成熟 CRUD API，完整版本历史，支持公司资料关联
- **Workspace UI**：草稿列表、搜索、过滤、删除
- **draftId 恢复**：`use-draft-loader.ts` hook，URL 参数加载

### 1.3 任务链现状

- **存储**：localStorage（key: `jueshi.taskChain.shippingMvp`）
- **UI**：TaskChainNextStep 组件 + 预填横幅
- **EventLog**：7 种事件全部覆盖
- **Save-to-Workspace**：占位入口（未登录→登录提示，已登录→即将开放）

## 二、ToolDocument 是否可复用

### 结论：不推荐复用

**理由**：
1. 语义不同：任务链是跨工具工作流，工具草稿是单工具表单
2. 污染现有系统：`toolKey = "task_chain_shipping"` 混入草稿列表
3. 无法按字段查询：`dataJson` 是字符串，无法过滤 hsCode / destinationCountry
4. 不支持匿名用户：userId 必填
5. 无法关联后续草稿：无 taskChainId 反向引用
6. 无状态管理：无 status / archivedAt / completedAt 字段

---

## 三、是否需要 TaskChainDraft 模型

### 结论：需要

**理由**：
1. 独立生命周期：draft → active → completed → archived
2. 跨草稿关联：一个任务链可关联多个 ToolDocumentDraft
3. 支持匿名用户：userId 可空，sessionId 标识
4. 独立展示：Workspace 任务区 vs 单据区
5. 可按字段查询：hsCode / destinationCountry / status 等

### 缺点

- ❌ 无法按字段查询

## 五、方案 B：新增 TaskChainDraft 模型

### 特点
- 新增独立模型 `TaskChainDraft`
- 独立生命周期
- 可关联多个 ToolDocumentDraft
- 支持匿名用户

### 数据模型

```prisma
model TaskChainDraft {
  id                  String    @id @default(cuid())
  userId              String?   // 可空（匿名用户）
  sessionId           String?   // 匿名用户标识
  sourceTool          String    // 来源工具
  title               String?
  productName         String?
  hsCode              String?
  productDescription  String?
  declaredValue       String?
  currency            String?
  exchangeRate        String?
  convertedValue      String?
  originCountry       String?
  destinationCountry  String?
  postalCode          String?
  addressText         String?
  shippingEstimate    String?
  nextStep            String?
  status              String    @default("draft")
  archivedAt          DateTime?
  completedAt         DateTime?
  createdAt           DateTime  @default(now())
  updatedAt           DateTime  @updatedAt

  @@index([userId])
  @@index([sessionId])
  @@index([status])
  @@map("task_chain_drafts")
}
```

ToolDocumentDraft 新增：
```prisma
model ToolDocumentDraft {
  // ... existing ...
  taskChainId String?  // 关联任务链
  @@index([taskChainId])
}
```

### 优点
- ✅ 语义清晰
- ✅ 独立生命周期
- ✅ 支持匿名用户
- ✅ 可关联后续草稿
- ✅ 独立展示
- ✅ 可按字段查询
- ✅ 不污染现有系统

### 缺点
- ❌ 需要 migration
- ❌ 需要新增 API（7 个）
- ❌ 需要新增 Workspace UI
- ❌ 开发成本较高（2-3 周）

### 风险
- 🟡 Migration 风险（可控）
- 🟡 维护复杂度增加（可控）
- 🟢 不污染现有系统

## 八、推荐方案

### 推荐：方案 B（新增 TaskChainDraft）

### 推荐理由

1. **语义最清晰**：任务链是独立概念，应有独立模型
2. **架构最合理**：不污染现有 ToolDocumentDraft 系统
3. **支持所有需求**：匿名用户、跨草稿关联、状态管理、独立展示
4. **长期可维护**：独立模型，不影响现有系统演进
5. **可扩展性好**：未来可增加工作流、自动化等功能

### 不推荐方案 A 的理由

- 语义不清，污染现有系统
- 无法按字段查询
- 不支持匿名用户
- 无法关联后续草稿
- 长期维护成本高

### 不推荐方案 C（长期使用）的理由

- localStorage 数据不可靠
- 无法跨设备同步
- 用户体验缺口大
- 只是过渡方案，最终还是要做后端

## 十三、localStorage 与后端同步风险

### 风险：🟡-🔴 中高

| 风险 | 等级 | 缓解 |
|---|---|---|
| 重复导入 | 🟡 中 | 导入后清除 localStorage |
| 数据冲突 | 🟡 中 | 后端优先，覆盖本地 |
| 多设备不同步 | 🔴 高 | Phase 2 后使用后端 |
| 清除缓存丢失 | 🔴 高 | 提示用户保存 |

### 缓解策略

1. 导入后清除 localStorage
2. 后端数据优先
3. 明确提示「仅保存在此浏览器」
4. 引导用户保存到工作台
