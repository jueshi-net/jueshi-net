## 〇、调研背景与定位校准

### 绝世百宝箱是什么

根据 `docs/PROJECT_MEMORY.md` 与 `docs/CONTENT_IA_LONG_TERM.md`：

- 本项目是**跨境电商 / 外贸 / 物流工具 SaaS**，核心链路是：
  `工具入口 → 使用工具 → 本地暂存 / 登录保存 → Workspace → 复用 / 导出 / 下一步工具 → 会员转化`
- **明确不是：** 单纯网址导航站、论坛优先项目、CMS、广告展示站。
- 已确立的内容漏斗：`专题（知识地图）→ 清单（行动指南）→ 工具（执行引擎）→ 用户资产（留存）`。

### 资源库（/resources）在其中的定位

资源库**不是终点站，而是分发器**：它的职责是把外部官方机构、第三方服务、社区资源、可下载工具/模板，分发到对应的「场景任务」里，并最终把用户引向站内工具或 Workspace。

> 一句话：资源库 = 站外资源的「索引层 + 信任层 + 关联层」，服务于场景任务，不服务于「收藏一堆网址」。

### 现状快照（V1，调研基线）

通过读取 `prisma/schema.prisma`、`src/app/(public)/resources/` 与 `src/app/api/resources/` 得到：

- **数据模型 `Resource`**：`name / url(unique) / description / category / tags[] / sourceType(official|third-party|internal) / usage / disclaimer / isActive / sortOrder`，外加高级字段 `favicon / iconUrl / isAd / domainAge / qualityScore / language / lastChecked / checkFailCount / rejectedReason`，以及推荐位字段 `isFeatured / featuredGroup / featuredOrder / featuredStartAt / featuredEndAt`。
- **路由**：`/resources`（目录首页，全量+推荐位，客户端分类筛选）；`/resources/[slug]`（**实为分类页**，slug 是分类名，非单条资源详情）；API 有 `GET /api/resources`、`GET /api/resources/featured`、`POST /api/resources/[id]/check-link`（死链检测）。
- **分类现状**：两处分类定义**不一致**——客户端用 `life/logistics/business/tools/templates/education/official/payment/ecommerce`；`[slug]` 页用 `starter/ai-tools/video-learning/overseas-life/business-tools/security/browser-extensions` + 4 个 legacy。V2 必须统一。
- **死链检测**：仅「按需 POST」触发，HEAD + GET 回退、8s 超时，但 `checkFailCount` 未真正自增、无定时任务、无失败阈值降级。
- **缺失项**（V2 需补）：国家/地区维度、风险等级、免费/付费、关联工具/指南/专题/清单、`community` 来源类型、真正的单条资源详情页、收藏到 Workspace。

## 一、WebStack 类网址导航

### 代表项目
- **WebStack.cc / WebStack-Laravel / WebStack-Hugo / WebStack-Guns**：开源网址导航体系，Laravel/Hugo/Springboot 多版本，静态与动态并存。

### 信息架构与交互模式
1. **左纵向分类 + 右网格卡片**：左侧固定分类树（常用/开发/设计/AI…），右侧按分类成块铺站点卡片。WebStack 的核心范式。
2. **站点卡片极简**：favicon + 名称 + 一句话描述，整卡可点外跳。
3. **顶部全局搜索**：跨分类关键词过滤，输入即筛。
4. **明暗主题 + 懒加载 + 拖拽排序**：管理员在后台拖拽调整分类与卡片顺序。
5. **后台驱动**：分类与卡片均入库管理，前端纯展示。
6. **搜索框可挂百度/谷歌**：把站内导航与外部搜索合一。

### ✅ 可借鉴
- **分类成块 + 卡片网格**的视觉密度与扫视效率，适合「资源目录页」骨架。
- **favicon + 名称 + 描述**的卡片最小信息单元，决定 V2 卡片的基础字段。
- **全局搜索 + 即时过滤**作为目录页的第一交互。
- **后台管理 + 前端展示**的职责分离（绝世已有 admin，天然契合）。
- **拖拽 sortOrder** 的运营手感。

### ❌ 不适用
- **纯外链终点站模型**：WebStack 的卡片点完即走，没有「场景、信任、关联、留存」——这与绝世「资源是分发器、要引向站内工具与 Workspace」的定位直接冲突。
- **无元数据信任层**：WebStack 不区分官方/第三方、不标风险、不查死链、不标免费/付费，无法满足跨境场景的合规与避坑需求。
- **分类树扁平且泛化**（常用/开发/设计）：跨境场景需要**任务导向**（寄件/做发票/查邮编）而非「工具品类」导向。
- **无国家/地区维度**：跨境场景强依赖国别，WebStack 完全没有。
- **明暗主题/外挂搜索引擎**等属于「个人书签站」诉求，与 SaaS 工具站调性不符，本期不做。

## 二、GitHub 开源导航 / Awesome 列表

### 代表项目
- **awesome-* 列表**（如 awesome-hacking-lists）、**stars 分组仓库**（duty9527/stars）、**OneNav / Flare / Pintree** 等自托管书签导航。

### 信息架构与交互模式
1. **README 即数据库**：用 Markdown 标题分大类、列表项即资源，Git 历史 = 变更日志。
2. **标签/主题（topics）分组**：GitHub Topics 把资源按主题聚合，star 数作为**社区质量信号**。
3. **社区贡献（PR）**：任何人可提交，维护者审核合并——众包策展。
4. **极简元数据**：名称 + 链接 + 一句描述，偶尔加 emoji 图标。
5. **Flare/OneNav**：把书签导出为导航页，支持轻量分组与搜索，资源占用极低。

### ✅ 可借鉴
- **「策展型」思路**：资源不是越多越好，而是精选 + 注解，这正是绝世 `qualityScore` 与 `rejectedReason` 的延续。
- **社区贡献通道**：未来可让用户「提交资源」，经管理员审核入库（绝世已有 feedback/community，可复用入口）。
- **star/质量信号**作为排序与推荐权重之一（对应 `qualityScore`、点击量、收藏量）。
- **主题（topic）作为横向切片**：一个资源可属多个主题，与绝世「专题（Topic）」天然对应。

### ❌ 不适用
- **README 编辑工作流**：绝世是 SaaS，资源必须入库 + 后台管理 + API 驱动，不能用 Markdown 文件当数据源。
- **无结构化元数据**：awesome 列表没有国家/风险/免费付费/死链状态，无法支撑 V2 卡片字段。
- **社区直接合并不审核**：跨境/外贸领域灰产与钓鱼站密集，必须人工 + AI 双重审核（绝世已有 `rejectedReason`），不能开放直接写入。
- **star 数不可控刷量**：不能直接拿第三方 star 当信任依据，需自有质量分体系。

## 三、行业资源导航（跨境/外贸/出海）

### 代表站点
- **GlobalTool.net（跨境网址导航）**、**跨境电商资源 GitHub 仓库（mswnlz/cross-border）**、**外贸平台盘点类文章**。

### 信息架构与交互模式
1. **场景分块**：收款 / 物流 / 选品 / 广告投放 / 建站 / 合规——按「卖家要做的事」切分，而非按工具品类。
2. **工具对比**：同场景下并列多个服务（如多个收款方案），含费率/地区/门槛对比。
3. **佣金/联盟导向**：多数此类站点以 CPA/返佣为盈利，推荐排序受佣金影响（隐性_bias）。
4. **国家/平台维度**：按目标市场（美国/欧洲/东南亚）或平台（Amazon/Shopify/TikTok）二次切分。
5. **更新频率低、死链多**：行业站普遍缺乏维护机制，链接腐烂严重。

### ✅ 可借鉴
- **场景分块（我要收款/我要物流/我要选品）**：与任务要求里的场景入口（我要寄件/做发票/查邮编…）完全同构，是 V2 首页场景入口的直接依据。
- **同场景工具对比**：V2 资源详情页可做「同类资源对比」模块。
- **国家/平台二次切分**：V2 的国家筛选维度由此而来。
- **场景 → 工具 → 单据/收款** 的串联，呼应绝世漏斗。

### ❌ 不适用
- **联盟佣金驱动的推荐排序**：绝世是工具 SaaS，推荐必须**后台可配 + 透明标注**（已有 `isAd`/`isFeatured`），且需明确区分广告位与编辑推荐，避免信任损耗。
- **低质链接农场**：行业站普遍无审核、无死链检测，绝世必须反其道而行（强制 `qualityScore` + 死链巡检 + `rejectedReason`）。
- **纯外跳无留存**：行业站不留存用户，绝世必须把资源收藏进 Workspace，形成资产。

## 四、自托管 Dashboard（Homepage / Dashy）——仅取信息架构

### 代表项目
- **Homepage（gethomepage）**、**Dashy（Lissy93/dashy）**。

> 仅借鉴 IA 与交互，不借鉴其自托管/YAML 配置/鉴权实现。

### 信息架构与交互模式
1. **Section + Widget 组合**：页面由多个 Section 组成，每个 Section 放若干 Widget（服务卡片/状态/统计/搜索）。
2. **状态指示（status/uptime）**：每个服务卡片可带在线状态点（绿/黄/红），由后端探活驱动。
3. **多布局（grid/columns）**：可配列数、分组、折叠。
4. **标签 + 搜索 + 收藏置顶**：Dashy 支持打标签、全局搜索、把常用项 pin 到顶部（个人化）。
5. **信息 Widget**：Homepage 支持非链接类 Widget（时钟、天气、统计、新闻），把「导航」升级为「信息面板」。
6. **多视图/多 Profile**：不同角色看不同面板。

### ✅ 可借鉴
- **Section + Widget 思路 → 场景区块 + 资源卡**：V2 首页用「场景入口区块」+「推荐位 Widget」+「分类目录 Widget」组合，而非纯列表。
- **状态指示点**：直接对应死链/可用性——V2 资源卡可显示「最近检测：可用 / 异常 / 未检测」，由 `lastChecked` + `checkFailCount` 驱动。
- **标签 + 搜索 + 置顶**：V2 已有 tags，可补「我的收藏置顶」（Workspace 收藏）。
- **个人化面板思路**：登录用户可在 Workspace 看到「我收藏的资源」聚合，呼应 Save to Workspace。
- **多视图/角色分流**：V2 首页场景入口可按身份（卖家/留学生/SOHO）分流，与 `CONTENT_IA_LONG_TERM.md` 的「场景入口按用户身份分流」一致。

### ❌ 不适用
- **YAML/JSON 手写配置**：绝世用 Prisma + 后台管理，配置不入文件。
- **自托管鉴权与 homelab 定位**：与 SaaS 多租户模型不符。
- **信息 Widget（时钟/天气/新闻）**：与跨境工具场景无关，不引入。
- **Widget 自由拼装**：SaaS 需要统一信息架构与视觉规范，不能让用户随意拼装布局，本期不做自定义面板。

## 五、跨境 / 外贸 / 海外生活资源站

### 代表站点
- **海外导航网（hhlink.com）**、**海外华人网站大全类站**、**跨境生活资源整理**。

### 信息架构与交互模式
1. **国家优先**：先选国家（美/英/澳/加/日…），再看该国生活资源。
2. **生活场景切分**：银行开户 / 汇款 / 租房 / 购物 / 医疗 / 办证 / 交通 / 社交。
3. **官方机构索引**：政府、税局、移民局、邮政等官方入口单独成区，强调权威性。
4. **华人视角注解**：对每个资源加「华人使用提示」（如某银行对非居民开户门槛）。
5. **质量参差、广告混杂**：多数老站 UI 陈旧、含大量联盟广告与失效链接。

### ✅ 可借鉴
- **国家优先的组织方式**：V2 必须把「国家筛选」提升为一等维度，与场景并列。
- **生活场景切分**：对应任务要求里的「我要留学/生活」「我要找官方机构」。
- **官方机构单独成区 + 权威标注**：V2 的 `sourceType=official` 与「官方/第三方/社区/工具」四级分类由此强化。
- **华人/出海视角注解**：对应 V2 卡片的 `usage`（使用提示）与 `disclaimer`（免责），是信任层的关键。
- **官方机构索引**：直接对应「我要找官方机构」场景。

### ❌ 不适用
- **老站 UI 与广告位堆砌**：视觉与商业模型都不适合 SaaS。
- **无死链维护、无质量审核**：恰恰是绝世要解决的痛点，不可沿用。
- **纯中文华人圈封闭视角**：绝世用户含外贸老手与海外本地化需求，资源需支持多语言（已有 `language` 字段），不能只做华人圈。

## 七、绝世百宝箱专属设计原则（V2 指导纲要）

> 以下 10 条原则直接驱动 `RESOURCE_NAVIGATION_IA_V2.md` 的设计决策。

### 原则 1：资源库是分发器，不是终点站
资源卡片的终点不是「点开外链」，而是「找到下一步该用什么站内工具/看什么指南/存进 Workspace」。每条资源都必须能**关联到站内工具、指南、专题、清单**，把外链回流进漏斗。

### 原则 2：任务场景为主轴，分类与国家为副轴
首页以「我要寄件 / 我要做发票 / 我要查邮编…」9 大场景入口为主轴；分类页与国家筛选为副轴检索。**不照搬 WebStack 的品类分类树**——跨境用户的思维是「我要做什么」而非「这是什么类型的工具」。

### 原则 3：信任层是第一公民
跨境/外贸领域灰产与钓鱼密集，资源库必须显式承载信任信息：
- **来源分级**：官方 / 第三方 / 社区 / 工具（站内）四级。
- **风险等级**：低/中/高三档，高风险资源强制免责声明。
- **质量分 + 拒绝原因**：AI 质量分驱动排序，灰产站直接 `rejectedReason` 拦截。
- **死链状态**：每卡显示最近检测时间与可用性，异常自动降级/隐藏。

### 原则 4：富元数据卡片，而非极简书签
卡片字段必须覆盖决策所需：标题、描述、国家、分类、来源、风险等级、免费/付费、最近检测、关联工具/指南/专题/清单。**宁可卡片信息密一点，也不要 WebStack 式的 favicon+名字两件套**——跨境用户需要判断「这站对我这个国家/这个场景适不适用、要不要钱、可不可信」。

### 原则 5：官方机构单独成区，权威可溯
官方机构（海关、税局、邮政、移民局、央行/金融监管）必须可单独筛选，并在卡片与详情页突出「官方」标识与原文链接。这是海外生活站与行业导航共同验证的刚需。

### 原则 6：推荐位后台可配，广告与编辑推荐严格分离
复用已有 `isFeatured`（编辑推荐，可时间窗调度）与 `isAd`（广告/Sponsored）。**推荐必须透明标注**，禁止联盟佣金隐性 bias 排序。推荐位由后台管理，前端只渲染。

### 原则 7：收藏到 Workspace，把外链变资产
资源可「保存到 Workspace」，与已有的 favorites/workspace 体系打通。登录用户的 Workspace 出现「我的资源收藏」聚合，形成个人化资产——这是 Dashboard 个人化思路的 SaaS 化落地，也是留存抓手。

### 原则 8：死链巡检制度化，非按需触发
现有按需 `check-link` 须升级为**定时巡检 + 失败阈值降级**：连续 N 次失败自动标记异常/下架，定时任务全量扫描，结果写回 `lastChecked`/`checkFailCount`。卡片与详情页据此显示可用性。

### 原则 9：统一分类体系，消除 V1 双源不一致
V1 客户端与 `[slug]` 页分类定义冲突，V2 必须有**单一事实源**（建议 `lib/resources/category-config.ts` 统一），分类既服务于场景映射，也服务于 URL（`/resources/category/[slug]`）。

### 原则 10：SaaS 调性，拒绝个人书签站化
不引入明暗主题切换、外挂搜索引擎、自由 Widget 拼装、YAML 配置等「个人书签站」特性。视觉与信息架构服从绝世整体 SaaS 规范，资源库是产品的一个模块，不是独立站点。

## 八、调研结论与 V2 输入清单

V2 设计须吸收的「borrowable」聚合：

1. **首页骨架** = 场景入口区块（行业导航场景分块）+ 推荐位 Widget（Dashboard Section 思路）+ 分类目录 + 全局搜索（WebStack）。
2. **卡片** = 富元数据（行业导航注解 + Dashboard 状态点 + 海外站官方标注）。
3. **检索** = 场景入口 + 国家筛选（海外站）+ 分类筛选（WebStack）+ 全局搜索（WebStack/Dashboard）。
4. **信任层** = 来源四级 + 风险等级 + 质量分 + 死链巡检（综合，绝世独有强化）。
5. **留存** = 收藏到 Workspace（Dashboard 个人化 SaaS 化）。
6. **关联** = 关联工具/指南/专题/清单（绝世漏斗串联，所有调研对象均缺失，是绝世差异化点）。
7. **维护** = 后台管理 + AI 审核 + 定时死链巡检（绝世已有基础，需制度化）。

V2 须明确拒绝的「not suitable」：

- WebStack 纯外链终点站模型与扁平品类树。
- Awesome 的 README 数据源与无审核社区合并。
- 行业站的联盟佣金 bias 与低质链接农场。
- Dashboard 的 YAML 配置、自托管鉴权、自由 Widget 拼装、信息 Widget。
- 海外生活站的陈旧 UI、广告堆砌、无维护机制、纯华人圈封闭视角。
