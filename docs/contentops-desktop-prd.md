## 2. 产品定位

**一句话定位:**  
面向内容运营团队的桌面端内容生产管理工具，统一管理多平台内容创作、SEO/GEO 优化、审核排期和发布分发。

**核心价值:**
- 集中管理内容生产全流程（从选题到发布）
- 桌面端提供流畅的编辑、审核、预览体验
- 服务器端负责安全的密钥管理和自动化发布
- 支持多平台内容分发（自有站点 + 第三方平台）
- 数据驱动的内容优化和刷新建议

## 4. 核心场景

### 场景 1: 内容生产全流程管理

**用户故事:**  
作为内容运营，我想在桌面端统一管理选题、创作、审核、排期，以便高效产出高质量内容。

**流程:**
1. 在选题池中添加新选题
2. 使用 AI 辅助生成内容大纲
3. 在内容编辑器中完成创作
4. 实时查看 SEO/GEO 评分
5. 提交审核并等待编辑确认
6. 设置发布时间
7. 查看发布状态和效果

### 场景 2: 多平台内容分发

**用户故事:**  
作为内容运营，我想一键将内容发布到多个平台，以便扩大内容覆盖范围。

**流程:**
1. 在平台预览中查看各平台适配效果
2. 选择目标平台（微信公众号、知乎、百家号等）
3. 系统自动生成平台适配版本
4. 人工确认后批量发布
5. 查看各平台发布状态和数据

### 场景 3: 内容优化和刷新

**用户故事:**  
作为 SEO 专员，我想监控内容表现并获得刷新建议，以便持续优化内容排名。

**流程:**
1. 查看内容表现数据（流量、排名、互动）
2. 识别需要刷新的旧内容
3. 接收 AI 生成的刷新建议
4. 编辑并重新发布
5. 监控刷新后的效果

## 5. 桌面端 vs Web 后台职责边界

### 桌面端 (ContentOps Studio)

**职责:**
- ✅ 内容创作和编辑（富文本编辑器）
- ✅ 内容审核和预览
- ✅ SEO/GEO 评分查看
- ✅ 发布排期管理（日历视图）
- ✅ 平台预览和适配
- ✅ 本地草稿缓存
- ✅ 发布日志查看
- ✅ 账号管理界面

**不负责:**
- ❌ 平台密钥存储
- ❌ 定时任务执行
- ❌ 实际发布操作
- ❌ 数据库直接访问

### Web 后台 (Server API)

**职责:**
- ✅ Content API（内容 CRUD）
- ✅ Draft API（草稿管理）
- ✅ Schedule API（排期管理）
- ✅ Publish Queue（发布队列）
- ✅ Platform Adapter（平台适配器）
- ✅ Credential Vault（密钥管理）
- ✅ Audit Log（操作日志）
- ✅ Retry Job（失败重试）

**为什么这样分工:**

| 考虑因素 | 桌面端 | 服务器端 |
|---------|--------|---------|
| **安全性** | 不存储敏感信息 | 安全存储密钥 |
| **可用性** | 离线编辑 | 7x24 运行 |
| **性能** | 流畅编辑体验 | 批量处理任务 |
| **扩展性** | 单用户使用 | 多用户并发 |

## 6. 为什么不是纯本地软件

### 6.1 必须使用服务器的原因

**1. 密钥安全**
- 平台 API 密钥（微信公众号、YouTube 等）必须安全存储
- 桌面端容易被反编译，密钥泄露风险高
- 服务器端可以使用专业的密钥管理服务（如 AWS KMS、HashiCorp Vault）

**2. 定时任务**
- 内容需要在指定时间自动发布
- 桌面端可能关闭，无法保证任务执行
- 服务器端可以 7x24 运行定时任务

**3. 多用户协作**
- 团队多人协作编辑和审核
- 需要中央化的内容存储和权限管理
- 服务器端提供统一的 API 接口

**4. 平台回调**
- 部分平台需要 Webhook 回调（如发布状态更新）
- 桌面端无法接收外部回调
- 服务器端可以接收并处理回调

**5. 数据备份**
- 内容数据需要定期备份
- 服务器端可以自动化备份流程
- 桌面端数据容易丢失

### 6.2 桌面端的优势

**1. 编辑体验**
- 富文本编辑器更流畅
- 支持本地文件拖拽
- 快捷键支持更完善

**2. 离线能力**
- 断网时可继续编辑
- 本地缓存草稿
- 网络恢复后同步

**3. 性能**
- 本地渲染，响应更快
- 大文件处理不卡顿
- 多标签页不占用浏览器资源

**4. 系统集成**
- 可以调用本地应用（如图片编辑器）
- 文件系统访问更方便
- 通知和提醒更及时

## 7. 为什么密钥必须放服务器

### 7.1 安全风险

**桌面端风险:**
- 代码可以被反编译
- 本地存储容易被访问
- 用户设备可能丢失或被盗
- 多用户共享设备时密钥泄露

**服务器端优势:**
- 专业的密钥管理服务
- 访问控制和审计日志
- 加密存储和传输
- 密钥轮换机制

### 7.2 合规要求

**平台要求:**
- 微信公众号要求密钥存储在安全环境
- YouTube API 要求 OAuth 2.0 密钥安全存储
- 知乎、百家号等平台有类似要求

**法律要求:**
- GDPR 要求保护用户数据
- 数据安全法要求加密存储敏感信息
- 平台协议要求保护 API 密钥

### 7.3 架构设计

```
桌面端
  ↓ HTTPS (短期 Session Token)
服务器端
  ↓ 加密存储
Credential Vault (密钥库)
  ↓ 安全调用
Platform API
```

**桌面端只持有:**
- 用户登录凭证（JWT Token）
- 短期访问令牌（24 小时过期）
- 本地草稿缓存（不含密钥）

**服务器端持有:**
- 平台 API 密钥（加密存储）
- OAuth Token（自动刷新）
- 发布队列和任务

## 11. 不做范围

**明确不做:**

1. **违规模拟登录**
   - 不使用 Selenium/Puppeteer 模拟用户操作
   - 不使用 Cookie 注入绕过登录
   - 不违反平台 ToS

2. **全自动批量发布**
   - 所有发布必须经过人工审核
   - 不自动批量发布低质内容
   - 不违反平台发布频率限制

3. **密钥本地存储**
   - 不在桌面端存储平台密钥
   - 不在本地存储 OAuth Token
   - 不在配置文件中保存敏感信息

4. **垃圾内容生成**
   - 不生成 AI 垃圾内容
   - 不批量生产低质内容
   - 不违反搜索引擎指南

5. **黑帽 SEO**
   - 不做关键词堆砌
   - 不做隐藏文本
   - 不做链接农场

## 13. 风险与缓解

### 13.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Tauri 兼容性问题 | 中 | 备选 Electron |
| 平台 API 变更 | 高 | 适配器模式，快速迭代 |
| 密钥泄露 | 高 | 专业密钥管理服务 |
| 定时任务失败 | 中 | 重试机制 + 告警 |

### 13.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 平台封禁 | 高 | 遵守平台规则，不违规 |
| 内容质量下降 | 高 | 人工审核 + 质量评分 |
| 用户流失 | 中 | 持续优化体验 |
| 竞品竞争 | 中 | 差异化定位 |

### 13.3 合规风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 违反平台 ToS | 高 | 使用官方 API，不模拟登录 |
| 数据泄露 | 高 | 加密存储，访问控制 |
| 版权问题 | 中 | 原创内容，引用标注 |
