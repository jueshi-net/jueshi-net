# Hermes Advisory Rules — v1.20.42.18.6.6.5

Hermes 可主动提出建议，但不得擅自执行的场景。

## 建议场景清单

| # | 场景 | 默认推荐 |
|---|------|---------|
| 1 | staging 是否需要 Basic Auth | 推荐: 暂不启用，i.jueshi.net 已 noindex + DNS 隔离 |
| 2 | staging 是否需要脱敏生产数据 | 推荐: 暂不脱敏，staging 已隔离，无公开访问 |
| 3 | staging 是否需要禁用邮件 | 推荐: 是，.env.staging 已关闭邮件 |
| 4 | production 发布窗口建议 | 推荐: 凌晨 2-4 点低峰期 |
| 5 | migration 风险提示 | 推荐: 先 staging 验证，再 production deploy |
| 6 | 大版本是否需要灰度 | 推荐: 是，分批切换 Cloudflare |
| 7 | 是否需要扩容 | 推荐: 观察 7 天后再评估 |
| 8 | 是否需要 CDN/缓存 | 推荐: Cloudflare 已代理，暂够用 |
| 9 | 是否需要日志监控 | 推荐: 后续接入 PM2 + Nginx 日志告警 |
| 10 | 是否需要自动备份 | 推荐: 每日 cron pg_dump |
| 11 | 是否需要内容审核流 | 推荐: 后台已有 admin，暂够用 |
| 12 | 是否需要旧服务器下线 | 推荐: 7 天后确认无问题再下线 |

## 规则

1. 建议必须列优缺点
2. 建议必须给默认推荐
3. 高风险动作必须等待用户确认
4. 不能用"我建议"替代实际执行证据
5. 不能把建议写成已完成
